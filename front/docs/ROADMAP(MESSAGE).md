- **두 독립 루트**: T1.1(EmployeePicker 승격)과 T1.2(message 스캐폴딩)는 서로 다른 관심사·파일이라 **상호 독립·병렬 착수 가능**. T1.1은 M3 작성 뷰(T4.1)의 공유 하드 의존이라 조기 착수 권장(단, M1·M2는 T1.1 불요).
- **T1.3(라우팅+사이드바)과 T1.4(건수+배지)는 둘 다 T1.2에만 의존** → 상호 독립·병렬. 단 T1.4의 배지는 T1.3이 사이드바 `쪽지함` 항목(`badgeKey`)을 추가한 뒤에야 **화면상 관찰**된다(카운트 훅 자체는 독립).
- **T2.2(목록 UI)는 T1.4(탭 건수 배지 소비)에 의존** → 건수 훅이 목록 탭 배지와 사이드바 배지에 **공유**된다(F1510 단일 소스).
- **M2 내부**: T3.1·T3.2·T3.4는 서로 다른 파일(api/훅)이라 병렬 착수 가능, T3.3(상세 UI)가 T3.1·T3.2를 조립. T3.4(생명주기 mutation)는 상세(T3.3)와 목록 행(T2.2) 양쪽에 배선.
- **M3 내부**: T4.1(폼/UI)·T4.2(발송/저장 mutation)는 상호 독립 → 병렬, T4.3(첨부 오케스트레이션)가 T4.1·T4.2를 조립. T4.4(답장)는 상세[답장](T3.3)+작성 뷰(T4.1) 합류 지점.
- **M4는 M3 작성 뷰(T4.1)를 편집 모드로 확장** — 작성/편집이 같은 뷰 컴포넌트라 T5.x는 T4.1 완성 후 착수.
