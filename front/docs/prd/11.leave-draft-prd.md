# 연가(Leave Draft) 작성/수정/조회·관리 Frontend MVP PRD

> 이 PRD는 전자결재 도메인 5분할 중 **④연가(휴가) 관심사** — 휴가 기안서(`leave` 슬롯 non-null)의 **작성(임시저장 생성 / 생성+상신)·수정**, **내 휴가(이력+잔여)·부서 휴가 관리·관리자 휴가 현황 조회**, 그리고 **상세 페이지의 연가 슬롯 본문 렌더** — 만 다룬다. 유형과 무관한 **상세조회·문서함 5종·상신/철회/취소·승인/반려/공람·첨부 뷰·결재대기함**은 **①공통(`docs/prd/7.approval-common-prd.md`, 구현 완료 `src/features/approval/**`)** 소유이며 여기서 재구현하지 않고 **소비**한다. 작성/수정 폼·유형 판별 술어·상세 본문 컴포넌트·`[수정]` 분기 배선은 **②일반(`docs/prd/8.general-draft-prd.md`)·③출장(`docs/prd/10.businesstrip-draft-prd.md`, 둘 다 구현 완료)** 이 확립한 선례를 **동형 복제**한다.
>
> **경계 요약** — ④가 소유: 휴가 기안 작성 페이지·수정 페이지, 내 휴가 페이지, 부서 휴가 관리 페이지, 관리자 휴가 현황 페이지, 그 API/mutation/query(11개 기능ID), 휴가 폼 zod 스키마, 휴가 상세 본문 컴포넌트(`LeaveDraftBody`, ①의 `DraftTypeBody` "준비 중" 폴백 교체), 상세 `[수정]` 버튼의 연가 분기 라우팅 배선, 유형 판별 술어 `isLeaveDraft`(슬롯-null), `LeaveSlot` 구체 타입 확정, 사이드바 "휴가 관리" 그룹 3항목. ④가 소비(①/②/③소유, 재구현 금지): `DraftDetailResponse.leave: LeaveSlot`(①타입, import/확정)·상세 페이지·`DrafterActions`(상신/철회/취소 + `[수정]` 노출 판정 `resolveDrafterActions.canEdit`)·`ApproverActions`(승인/반려)·**결재대기함**(`PendingApprovalDraftsPage`, F711 결재자 상세 진입 표준 경로)·`EmployeePicker`(결재선 선택)·`ApproverParam`·`approvalKeys`·`useDraftDetailQuery`(수정 프리필)·첨부 업로드(F716)·`usePrimaryDeptId`(근태)·`PaginationControls`/`usePageState`. 배관: axios·QueryClient·`handleApiError`·`ProtectedRoute`·LayoutShell·`useZodForm`/`submitWithErrorMapping`·shadcn 폼·sonner·dayjs.
>
> **얽힘 확인(결정 사항)** — `api-endpoint.md` 전수 검색 결과 "휴가/연차/leave" 관련 기능ID는 아래 11개가 전부다(DRAFT/DOCUMENT API 5개 + EMP LEAVE/DEPT API 6개). ④가 11개 기능ID 전부를 단독 소유한다(얽힘 없음).

## 🎯 핵심 정보

- **목적**: 활성 사원이 **휴가 기안서(제목·본문·휴가 유형·시작/종료 일시·결재선·첨부)** 를 작성해 임시저장하거나 바로 상신하고, 상신 전(UNSUBMITTED) 기안을 수정하며, **본인 휴가 이력·잔여**를 열람한다. 부서 매니저는 부서원 휴가 신청 이력·잔여·연차 사용률을, 관리자는 전사/부서 연차 사용률·사원 휴가 요약을 조회하고 특정 사원의 특별/포상 휴가 부여일수를 조정한다. 작성 후에는 ①공통의 상세·문서함·워크플로우로 이어진다.
- **사용자**: 작성·수정·내 휴가(이력/잔여)는 최소 요구 role `EMPLOYEE`(활성 사원, 수정은 **기안자 본인**만 — 서버 최종 판정). **부서 휴가 관리는 최소 요구 role `DEPT_MANAGER`**(같은 부서). **관리자 휴가 현황은 `ADMIN` 전용**. `ADMIN`은 RoleHierarchy상 하위 메뉴 자동 포함. 휴가 기안 승인/반려는 결재선에 지정된 결재자(role·부서 무관, 서버 판정)가 **결재대기함**(①)을 통해 상세로 진입해 처리한다.

  ├ 신청 이력 목록(approvalStatus/yearMonth 필터, 배열 응답=비페이징)
  ├ [휴가 신청] 버튼 → 휴가 기안 작성 페이지
  └ 이력 행 클릭 → 기안서 상세 페이지(①)

[휴가 기안 작성 페이지] (내 휴가 → [휴가 신청]로 진입)
  ├ 제목·본문 + 휴가 유형(leaveType)·시작/종료 일시 + 결재선(EmployeePicker=①) + (선택) 첨부

  └ [생성 후 상신](LEAVE_DRAFT_CREATE_SUBMISSION, 201 {draftId}, 결재선 최소 1명 사전검증)
       └ 성공 → 생성된 기안 상세 페이지(①, WAITING)

[전자결재 > 임시저장함(①) 또는 내 휴가 이력] → 행 클릭 → 기안서 상세 페이지(①)
  ├ 본문 = 휴가 상세 본문(LeaveDraftBody=④가 DraftTypeBody 폴백 교체): 유형·기간·reservedHours 렌더

  │     └ [저장](LEAVE_DRAFT_UPDATE, 204) → 성공 → 상세 페이지로 복귀
  ├ (기안자·WAITING/IN_PROGRESS) [상신 철회]·(APPROVED) [취소 기안 작성] — ①소유

[사이드바 "휴가 관리 > 부서 휴가 관리"] (DEPT_MANAGER 이상 노출) → 부서 휴가 관리 페이지
  ├ 탭① 신청 이력(DEPT_LEAVE_REQUEST_HISTORY, 페이징): 부서원 검색·상태·월 필터 → 행 클릭 → 상세(①)

**권한 분기점**

- 라우트 가드(Layer 1): 미인증 → 로그인 리디렉션(auth 관할). 작성·수정·내 휴가 라우트는 최소 요구 role `EMPLOYEE`. **부서 휴가 관리 라우트는 사이드바 minRole `DEPT_MANAGER`**, **관리자 휴가 현황 라우트는 `ADMIN`**(근태 `/attendance/dept` 컨벤션 동일 — 라우트는 `ProtectedRoute`, 최종 판단은 서버 403).
- 서버 최종 판단(role 아닌 문서-사원 관계):
  - **작성**(`LEAVE_DRAFT_CREATE`/`_CREATE_SUBMISSION`)은 활성 사원. 비활성·미승인 사원은 서버 도메인 에러로 막음.
  - **수정**(`LEAVE_DRAFT_UPDATE`)은 **기안자 본인 + 대상 UNSUBMITTED**만. 그 외 접근 시 서버 403/도메인 에러 → 권한 부족/처리 불가 UX(재발급 금지, 에러코드 비의존).
  - **부서 조회**(`DEPT_LEAVE_REQUEST_HISTORY`/`DEPT_EMP_LEAVE_SUMMARY`/`DEPT_EMP_LEAVE_USAGE_SUMMARY`)는 **같은 부서 매니저 또는 ADMIN**만 → 타 부서 `deptId` 접근 시 서버 403(`ROLE_003`) UX(`handleApiError` 토스트). `{deptId}`는 `usePrimaryDeptId()`(strict, 근태 재사용) 도출.
  - **관리자 조회·조정**(`EMP_LEAVE_*`)은 `ADMIN` 단일 게이트(서버 최종 판단 없음).
  - **상신 시 결재선** 최소 1명 필요(도메인 규칙) → 서버 최종 판정. 프론트는 `[생성 후 상신]`에서 결재선 사전검증(②Open Q#1 정책 복제).

### 2. MVP 필수 지원 기능 — 신규 기능ID 없음(①/②/③공통 자산 소비·배선만)

④는 다음을 **재구현하지 않고 소비하거나, ①소유 지점에 배선만** 추가한다(경계 = 헤더 인용 블록):

- **휴가 상세 본문 렌더(`LeaveDraftBody`)** — ①의 `DraftTypeBody`가 현재 `draft.leave != null`이면 "휴가 기안 본문 화면은 준비 중입니다" 폴백(`TypeSlotFallback`)을 렌더한다(`components/detail/DraftTypeBody.tsx:29-31`). ④는 이 분기를 **실제 휴가 본문 컴포넌트로 교체**한다(③`BusinessTripDraftBody`와 동형): `leave` 슬롯(`startAt`·`endAt`·`leaveType`·`reservedHours`)과 공통 `content`를 렌더. 데이터는 `DRAFT_DETAIL`(F701, ①)이 이미 내려준 `leave` 슬롯 소비 — 신규 조회 없음. 기간/시각 포맷은 dayjs(`formatDraftDateTime` 재사용).
- **`LeaveSlot` 구체 타입 확정** — 현재 `model/draftDetail.ts`의 `LeaveSlot = Record<string, unknown>`(①이 슬롯 미확정으로 남겨둠)을 `{ startAt, endAt, leaveType, reservedHours }` 구체 타입으로 좁힌다. 백엔드 DTO(`DraftDetailResponse.LeaveDraftDetail`) 소스 대조로 확정 완료(Open Q#4 해결) — `leaveType`은 enum 코드 그대로 내려온다(이력 목록의 표시명 문자열과 다름, 혼동 주의).
- **상세 `[수정]` 연가 분기 배선(F741 진입)** — ①의 `DrafterActions.handleEdit`는 현재 `isGeneralDraft`·`isBusinessTripDraft`만 분기하고 나머지는 "준비 중" 토스트 폴백이다(`components/detail/DrafterActions.tsx:69-79`). ④는 **`isLeaveDraft(draft)` 분기를 추가**해 휴가 기안 수정 페이지로 `navigate`한다. 노출 판정(`canEdit` = 기안자 + UNSUBMITTED)은 ①이 이미 계산(재작성 금지). 매출은 ⑤ 착수 전까지 폴백 유지.
- **유형 판별 술어 `isLeaveDraft`** — `③isBusinessTripDraft`(`draft.businessTrip != null`)와 동형으로 `draft.leave != null`(`lib/isLeaveDraft.ts`). `draftType` 문자열 비교 금지(백엔드 `getClass().getSimpleName()`, 스니펫 값 outdated). 상세 `[수정]` 라우팅과 수정 페이지 진입 가드가 공유.
- **`EmployeePicker`(제어형)·`ApproverParam{approverId,role,order}`** — 결재선 선택 UI·payload 타입. 선택 순서 → `order`(1-base), `role`='APPROVER' 고정(②③선례 동일). **옛 PRD Open Q#1(결재자 사원 검색 경로)은 여기서 해소** — ②③이 `EmployeePicker`(부서→부서원 `DEPT_MEMBERS`+`DEPTS`)로 이미 확립한 선례를 그대로 재사용한다.
- **결재대기함(`PendingApprovalDraftsPage`, F711)** — 결재선 결재자(role·부서 무관)가 휴가 기안 상세로 진입해 승인/반려하는 표준 경로. **이미 "전자결재" 그룹에 구현·배선되어 있음**(옛 PRD가 "휴가 관리" 그룹에 임시로 넣었던 결재대기함 슬롯은 불필요 — 제외). ④는 별도 조치 없음.
- **`usePrimaryDeptId`(`src/features/attendance/model/usePrimaryDeptId.ts`)** — 부서 휴가 관리 `{deptId}` path param 도출(strict, 폴백 없음, `undefined` → 게이팅). 근태·③출장 컨벤션 동일 재사용.
- **첨부 업로드 F716 `DRAFT_FILE_UPLOAD`(`useDraftFileUploadMutation`)** — 생성 응답 `draftId`로 재사용(②③와 동일, 상세 첨부 영역=①에서 관리 권고). 파일 정책 `@docs/backend-contract/file-upload.md` + `@../docs/도메인모델.md`(Open Q#6).
- **폼/목록 배관** `useZodForm`/`submitWithErrorMapping`(`@/shared/lib/form`)·`handleApiError`·`approvalKeys`(성공 후 `all` invalidate)·`PaginationControls`/`usePageState`(부서/관리자 목록 페이징) — ②③·근태 선례 동일.

```
📱 HARUON 내비게이션 (EMPLOYEE 공통 · 최소 요구 role 표기)
└── 🌴 휴가 관리 (그룹 · 기존 sidebarMenuItems.ts "휴가 관리" 슬롯 재사용, minRole: EMPLOYEE)
     ├── 내 휴가 — F742·F743 (+진입: 휴가 신청 F740 / 수정 F741) (minRole: EMPLOYEE)   ← placeholder 승격
     ├── 부서 휴가 관리 — F744·F745·F746 (minRole: DEPT_MANAGER)                       ← placeholder 승격
     └── 관리자 휴가 현황 — F747·F748·F749·F750 (minRole: ADMIN)                        ← 신규 슬롯 추가

📁 전자결재 그룹의 "결재대기함"(①, F711) — 휴가 결재자 상세 진입 표준 경로(이미 구현, ④ 조치 없음)
```

- 기존 `src/shared/components/sidebarMenuItems.ts`의 "휴가 관리" 그룹 placeholder 2개(`내 휴가 요약` `EMPLOYEE` / `부서 휴가 관리` `DEPT_MANAGER`)를 실 라우트로 승격(`implemented` 제거 + `to`)한다. `내 휴가 요약`은 잔여+이력을 함께 다루므로 라벨을 **"내 휴가"**로 조정한다. **"관리자 휴가 현황"(`minRole: 'ADMIN'`)** 은 같은 그룹에 신규 슬롯 추가(placeholder에 없으므로 추가 — 도메인 내 메뉴, 발명 아님).
- **결재대기함 슬롯은 "휴가 관리" 그룹에 두지 않는다.** `MY_PENDING_APPROVAL_DRAFTS`는 ①공통이 이미 "전자결재" 그룹에 구현했다(옛 PRD의 임시 배치는 폐기). 휴가 결재자는 그 경로로 상세에 진입한다.
- **휴가 기안 작성/수정·상세는 별도 메뉴가 아니다.** 작성은 "내 휴가" 페이지 [휴가 신청] 버튼으로, 수정은 상세 [수정]으로 진입하는 하위 라우트다(②③의 작성/수정과 동일 — 상세/이력 경유). 부서 휴가 관리·관리자 휴가 현황은 `minRole`로 `hasRequiredRole`가 자동 게이팅(비대상에게 미노출), `ADMIN`은 RoleHierarchy상 전 메뉴 자동 포함.

### 기안서 상세 페이지 — 휴가 본문 렌더·`[수정]` 진입 배선 (①소유 페이지에 ④ 배선 추가)

**계약 실측 메모:**
- **`LeaveType`(작성 request-fields 실측 "예: ANNUAL, HOURLY, SICK, OFFICIAL, COMPENSATORY, SPECIAL"):** 작성 폼은 이 6개 enum 코드 중 택1을 전송한다. 도메인모델 라벨(추정): ANNUAL(연차)·HOURLY(시간/공휴일※)·SICK(병가)·OFFICIAL(공가)·COMPENSATORY(대체휴무)·SPECIAL(특별휴가). ※HOURLY 라벨 모호 → Open Q#3.
- **이력 `leaveType`은 표시명 문자열:** `MY_/DEPT_LEAVE_REQUEST_HISTORY` 응답의 `leaveType`은 enum 코드가 아니라 서버 표시명("연차"·"반차")이다. `requestedLeaveDays`가 0.5이면 서버가 "반차"로 표기하는 등 유형+일수 파생 라벨이 내려온다 → 목록은 표시명을 그대로 렌더(클라 매핑 불필요). 반면 필터 `approvalStatus`는 **enum 코드**(`UNSUBMITTED/WAITING/IN_PROGRESS/APPROVED/REJECTED`)로 전송한다.
- **작성/수정 body 혼합 구조(⚠️ 평탄화 금지):** `param{title,content,approvers?}`는 ②일반 body와 동일 형태이나, 휴가는 그 옆에 `startAt/endAt/leaveType`이 **최상위 형제**로 붙는다(③출장의 `startAt/endAt/destination/purpose/participantIds`와 동형 구조, 필드만 다름). `approvers` 항목 필드명은 `approverId`/`role`/`order` — 기존 `ApproverParam` 그대로.
- **요약 응답 `empId` 실측 확인:** `DEPT_EMP_LEAVE_SUMMARY`·`EMP_LEAVE_SUMMARY` 응답 `content[]`에 `empId:Number`가 맨 앞 필드로 포함됨을 스니펫에서 재확인했다(옛 PRD Open Q#5의 백엔드 보강이 반영된 상태). F747 요약 행의 `empId`를 F749/F750 path에 그대로 사용 — 별도 사원 검색 불필요.
- **응답 코드:** 두 생성 API 모두 `201` + `{ draftId }` → 생성 후 `/approval/drafts/{draftId}` 상세 이동(②③선례). 수정·조정은 `204` Empty.
- **첨부 정책(drafts 도메인, ①실측):** 확장자/용량은 게시판 동일, **기안서당 최대 10개·총 10MB**(도메인모델). 위반 에러 `FILE_001~005`. 상세 정책은 `@../docs/도메인모델.md` 참조(Open Q#6).

## ❓ Open Questions (계약 공백 — 개발 착수 전 확인 필요)

1. **상신 시 결재선 필수 검증 위치(②Open Q#1 계승).** `LEAVE_DRAFT_CREATE_SUBMISSION`의 `param.approvers`는 optional로 문서화되나 도메인 규칙은 "상신=결재자 ≥1"이다. 권고안: `[임시저장으로 생성]`은 결재선 없이 허용, `[생성 후 상신]`은 결재선 ≥1 클라 사전검증(②③`CreatePage` 동일). 최종 판정 서버.
2. **잔여 초과 사전 검증 여부(옛 PRD #2 계승).** 도메인상 사용일수 차감은 결재완료 이후이고 초과는 서버가 판정한다. 프론트는 잔여만 표시하고 상신은 서버 판정에 맡기는 것으로 가정 — 신청 단계 사전 경고 UX가 필요한지 확인.
3. **`HOURLY` 휴가 유형 라벨·`reservedHours` 표기(옛 PRD #3 계승).** enum description이 "공휴일"인데 "연가 1시간 단위 사용"(도메인모델) 규칙과 함께 보면 시간 단위 연차를 의미할 여지가 있다. 작성 폼의 유형 라벨과 상세 본문 `reservedHours` 표기 규칙("n시간")·반차/시간연차 파생 표기 규칙 확정 필요.
4. **(해결됨) `LeaveSlot` 하위필드.** `DRAFT_DETAIL` 스니펫 예시가 BUSINESS_TRIP이라 스니펫만으로는 미관측이었으나, 백엔드 DTO 소스(`back/src/main/java/.../draft/service/query/dto/response/DraftDetailResponse.java:61-67`)를 직접 대조해 확정했다: `public record LeaveDraftDetail(LocalDateTime startAt, LocalDateTime endAt, LeaveType leaveType, Long reservedHours)`. 즉 `LeaveSlot = { startAt: ISO_DATE_TIME, endAt: ISO_DATE_TIME, leaveType: LeaveType, reservedHours: number }` — 옛 PRD(#6.leave-prd.md §참조 계약 매핑)의 실측값과 정확히 일치한다. `leaveType`은 `LeaveType.java`에 `@JsonValue`/커스텀 직렬화가 없어 **enum 코드 그대로**("ANNUAL" 등) 내려온다(작성 요청 body의 `leaveType`과 동일 표현 — 이력 목록 `MY_LEAVE_REQUEST_HISTORY`의 `leaveType`이 표시명 문자열("연차")로 매핑되는 것과 다르므로 혼동 주의). live UX 재확인은 선택사항으로 낮춘다.
5. **휴가 기안 첨부파일 범위(옛 PRD #6 계승).** 상세 응답 `files[]`는 표시하나(①소유), 작성 폼에서 첨부 업로드(F716)를 포함할지 상세 첨부 영역(①)에서만 관리할지 확정 필요. 정책은 `@docs/backend-contract/file-upload.md` + `@../docs/도메인모델.md` 위임. 권고: ②③선례대로 작성 폼은 첨부 없이 생성 → 상세에서 관리.
