# 출장 기안(Business Trip Draft) 작성/수정/이력 Frontend MVP PRD

> 이 PRD는 전자결재 도메인 5분할 중 **③출장 기안 관심사** — 출장 기안서(`businessTrip` 슬롯 non-null)의 **작성(임시저장 생성 / 생성+상신)·수정·참여자 전량 교체**와 **내/부서 출장 신청 이력 조회** — 만 다룬다. 유형과 무관한 **상세조회·문서함 5종·상신/철회/취소·승인/반려/공람·첨부 뷰**는 **①공통(`docs/prd/7.approval-common-prd.md`, 구현 완료 `src/features/approval/**`)** 소유이며 여기서 재구현하지 않고 **소비**한다. 일반 기안 작성/수정 폼·파일 컨벤션은 **②일반 기안(`docs/prd/8.general-draft-prd.md`, 구현 완료)** 이 확립한 선례를 **동형 복제**한다.
>
> **경계 요약** — ③이 소유: 출장 기안 작성 페이지·수정 페이지, 참여자 수정 다이얼로그, 내/부서 출장 이력 페이지, 그 API/mutation/query(6개 기능ID), 출장 폼 zod 스키마, 출장 상세 본문 컴포넌트(`BusinessTripDraftBody`, ①의 `DraftTypeBody` "준비 중" 폴백 교체), 상세 `[수정]` 버튼의 출장 분기 라우팅 배선, 유형 판별 술어 `isBusinessTripDraft`(슬롯-null), 사이드바 출장 항목. ③이 소비(①/②소유, 재구현 금지): `DraftDetailResponse.businessTrip: BusinessTripSlot`(①실측 확정 타입, import), 상세 페이지·`DrafterActions`(`resolveDrafterActions.canEdit`)·`EmployeePicker`(결재선·참여자 공용)·`ApproverParam`·`approvalKeys`·`useDraftDetailQuery`(수정 프리필)·첨부 업로드(F716)·`usePrimaryDeptId`(근태 도메인)·`CirculationAddDialog`(다이얼로그 선례). 배관: axios·QueryClient·`handleApiError`·`ProtectedRoute`·LayoutShell·`useZodForm`/`submitWithErrorMapping`·shadcn 폼·`PaginationControls`/`usePageState`·sonner·dayjs.
>
> **얽힘 확인(결정 사항)** — `api-endpoint.md` 전수 검색 결과 "출장" 관련 기능ID는 이 6개가 전부다. 별도의 "개인출장" 도메인/기능ID는 존재하지 않는다. **이 PRD가 6개 기능ID 전부를 단독으로 소유**하며 `docs/COMPLICATED-DOMAIN.md`에 넘길 항목 없음(얽힘 없음).
>
> 전역 계약(인증·reissue·에러·`ROLE_003`·페이징·날짜 dayjs·`withCredentials`)은 CLAUDE.md §7 `BACK-END 계약 문서` 관할이며 재서술하지 않는다.

## 🎯 핵심 정보

- **목적**: 활성 사원이 **출장 기안서(제목·본문·출장 기간·목적지·목적·참여자·결재선·첨부)** 를 작성해 임시저장하거나 바로 상신하고, 상신 전(UNSUBMITTED) 기안을 수정(참여자는 별도 다이얼로그로 전량 교체)하며, **본인/부서의 출장 신청 이력**을 조회하는 화면을 구성한다. 작성 후에는 ①공통의 상세·문서함·워크플로우로 이어진다.
- **사용자**: 작성·수정·참여자 교체·내 이력은 최소 요구 role `EMPLOYEE`(활성 사원, 수정/참여자 교체는 **기안자 본인**만 — 서버 최종 판정). **부서 출장 이력은 최소 요구 role `DEPT_MANAGER`**(같은 부서, `ADMIN`은 RoleHierarchy상 포함).

## 🚶 사용자 여정

```
[사이드바 "전자결재 > 출장 기안 작성"] → 출장 기안 작성 페이지
  ├ 제목·본문 + 출장 기간(startAt<endAt)·목적지·목적 입력 + 결재선 지정(EmployeePicker=①) + (선택) 참여자 지정(EmployeePicker=①) + (선택) 첨부
  ├ [임시저장으로 생성](BUSINESS_TRIP_DRAFT_CREATE, 201 {draftId})
  │    └ 성공 → 생성된 기안 상세 페이지(①) → (기안자·UNSUBMITTED) 상신/수정/참여자 수정/첨부
  └ [생성 후 상신](BUSINESS_TRIP_DRAFT_CREATE_SUBMISSION, 201 {draftId}, 결재선 최소 1명 사전검증)
       └ 성공 → 생성된 기안 상세 페이지(①, WAITING)

[전자결재 > 임시저장함(①) 또는 내 출장 이력] → 행 클릭 → 기안서 상세 페이지(①)
  ├ 본문 = 출장 상세 본문(BusinessTripDraftBody=③가 DraftTypeBody 폴백 교체): 기간·목적지·목적·참여자 렌더
  ├ (기안자·UNSUBMITTED) [수정] 버튼(DrafterActions=①) → isBusinessTripDraft 분기(③배선) → 출장 기안 수정 페이지
  │     ├ 기존 값 프리필(DRAFT_DETAIL 소비=①) — 참여자 제외(별도 API)
  │     └ [저장](BUSINESS_TRIP_DRAFT_UPDATE, 204) → 성공 → 상세 페이지로 복귀
  └ (기안자·UNSUBMITTED) [참여자 수정] 버튼(출장 본문 내) → 참여자 다이얼로그(기존 참여자 선반영)
        └ [저장](BUSINESS_TRIP_PARTICIPANTS_UPDATE, 204, 빈 배열 불가·전량 교체) → 상세 갱신

[사이드바 "전자결재 > 내 출장 이력"] → 내 출장 이력 페이지(MY_BUSINESS_TRIP_REQUEST_HISTORY)
  └ 행 클릭 → 기안서 상세 페이지(①)

[사이드바 "전자결재 > 부서 출장 이력"] → 부서 출장 이력 페이지(DEPT_BUSINESS_TRIP_REQUEST_HISTORY)
  └ (DEPT_MANAGER/ADMIN, deptId=usePrimaryDeptId) 행 클릭 → 기안서 상세 페이지(①)
```

**권한 분기점**

- 라우트 가드(Layer 1): 미인증 → 로그인 리디렉션(auth 관할). 작성·수정·참여자·내 이력 라우트는 최소 요구 role `EMPLOYEE`. **부서 출장 이력 라우트만 사이드바 minRole `DEPT_MANAGER`**(라우트는 `ProtectedRoute`만, 근태 `/attendance/dept` 컨벤션 동일 — 별도 RoleGuard 없이 서버 403이 최종 판단).
- 서버 최종 판단(role 아닌 문서-사원 관계):
  - **작성**(`BUSINESS_TRIP_DRAFT_CREATE`/`_CREATE_SUBMISSION`)은 활성 사원. 비활성·미승인 사원은 서버 도메인 에러로 막음.
  - **수정**(`BUSINESS_TRIP_DRAFT_UPDATE`)·**참여자 교체**(`BUSINESS_TRIP_PARTICIPANTS_UPDATE`)는 **기안자 본인 + 대상 UNSUBMITTED**만(수정과 동일 전제로 가정 — Open Q#3). 그 외 접근 시 서버 403/도메인 에러 → 권한 부족/처리 불가 UX(재발급 금지, 에러코드 비의존).
  - **부서 출장 이력**(`DEPT_BUSINESS_TRIP_REQUEST_HISTORY`)은 **같은 부서 매니저 또는 ADMIN**만. 타 부서 접근 시 서버 403(`ROLE_003`) → 안내 토스트(`handleApiError` 단일 진입점). `{deptId}`는 `usePrimaryDeptId()`(strict, 근태 재사용)로 도출.
  - **상신 시 결재선** 최소 1명 필요(도메인 규칙) → 서버 최종 판정. 프론트는 `[생성 후 상신]`에서 결재선 사전검증(②Open Q#1 정책 복제).

### 2. MVP 필수 지원 기능 — 신규 기능ID 없음(①/②공통 자산 소비·배선만)

③은 다음을 **재구현하지 않고 소비하거나, ①소유 지점에 배선만** 추가한다(경계 = 헤더 인용 블록):

- **출장 상세 본문 렌더(`BusinessTripDraftBody`)** — ①의 `DraftTypeBody`가 현재 `draft.businessTrip != null`이면 "출장 기안 본문 화면은 준비 중입니다" 폴백을 렌더한다(`components/detail/DraftTypeBody.tsx`). ③은 이 분기를 **실제 출장 본문 컴포넌트로 교체**한다: `businessTrip` 슬롯(기간 `startAt~endAt`·`destination`·`purpose`·`participants[]`)과 공통 `content`를 렌더. 데이터는 `DRAFT_DETAIL`(F701, ①)의 `BusinessTripSlot`(①실측 확정 타입 import) 소비 — 신규 조회 없음.
- **상세 `[수정]` 출장 분기 배선** — ①의 `DrafterActions.handleEdit`는 현재 `isGeneralDraft(draft)`만 분기하고 나머지는 "준비 중" 토스트 폴백이다(`components/detail/DrafterActions.tsx:67-73`). ③은 **`isBusinessTripDraft(draft)` 분기를 추가**해 출장 기안 수정 페이지(`/approval/drafts/business-trips/{draftId}/edit`)로 `navigate`한다. 노출 판정(`canEdit` = 기안자 + UNSUBMITTED)은 ①이 이미 계산(재작성 금지). 휴가/매출은 각 유형 PRD 착수 전까지 폴백 유지.
- **유형 판별 술어 `isBusinessTripDraft`** — `②isGeneralDraft`(슬롯-null)와 동형으로 `draft.businessTrip != null`(`lib/isBusinessTripDraft.ts`). `draftType` 문자열 비교 금지(백엔드 `getClass().getSimpleName()`, 스니펫 값 outdated). 상세 `[수정]` 라우팅과 수정 페이지 진입 가드가 공유.
- **`EmployeePicker`(제어형)** — 결재선(`param.approvers`)과 참여자(`participantIds`) **양쪽에 공용 재사용**. 결재선: 선택 순서 → `order`(1-base), `role`='APPROVER' 고정 → `ApproverParam[]`. 참여자: `selected.map(e=>e.empId)` → `number[]`.
- **`useDraftDetailQuery`(F701)** — 수정 페이지 프리필·본문 렌더·참여자 다이얼로그 선반영 소스.
- **첨부 업로드 F716 `DRAFT_FILE_UPLOAD`(`useDraftFileUploadMutation`)** — 생성 응답 `draftId`로 재사용(②와 동일, 상세 첨부 영역=①에서 관리 권고). 파일 정책 `@docs/backend-contract/file-upload.md` + `@../docs/도메인모델.md`.
- **`usePrimaryDeptId`(`src/features/attendance/model/usePrimaryDeptId.ts`)** — 부서 출장 이력 `{deptId}` path param 도출(strict, 폴백 없음, `undefined` → 게이팅). 근태 `DeptAttendancePage` 컨벤션 동일 재사용.
- **폼/목록 배관** `useZodForm`/`submitWithErrorMapping`(`@/shared/lib/form`)·`handleApiError`·`approvalKeys`(성공 후 `all` invalidate)·`PaginationControls`/`usePageState`(부서 이력 페이징) — ②·근태 선례 동일.

### 3. MVP 이후 기능 / 범위 외 (이번 PRD 명시적 제외)

- **타 유형 슬롯 작성/수정 전부**: `GENERAL_DRAFT_*`(②일반), `LEAVE_DRAFT_*`(④연가), `SALES_DRAFT_*`(⑤매출) — 각 유형 PRD 관할. ③은 출장만.
- **상세조회·문서함 5종·상신/철회/취소·승인/반려·공람·첨부 뷰·워크플로우 액션** — ①공통 소유.
- **첨부 후처리(미리보기/다운로드/삭제)** — 상세 첨부 영역(F717~F719)으로 ①소유. ③의 작성 폼은 **업로드 진입만**(권고: 상세에서 관리).
- **결재선 협조 결재자(`COOPERATOR`) 역할 지정 UI** — MVP 범위 밖(APPROVER 고정, ②선례).
- **참여자 add/remove 세분 조작** — 계약이 **전량 교체(bare array)** 뿐이라 부분 add/remove 의미 부여 금지(필드표 근거 없음).
- **테마/다크모드·다국어(i18n)·브라우저 푸시 알림** — 전 도메인 공통 제외.

```
     ├── 부서 출장 이력 — F734 (minRole: DEPT_MANAGER)        ← ③ 추가 (ADMIN 자동 포함)
     └── (하위·비노출) 출장 기안 수정 — F731 / 참여자 수정 — F732
          F731 진입: 임시저장함/내 출장 이력(①) → 상세(①) → [수정](DrafterActions=①, ③배선) → 출장 기안 수정 페이지
          F732 진입: 상세(①) → 출장 본문(BusinessTripDraftBody=③) → [참여자 수정] → 다이얼로그
```

- "전자결재" 그룹(`src/shared/components/sidebarMenuItems.ts`, `label: '전자결재'`)에 **출장 항목 3개**(출장 기안 작성 `EMPLOYEE`, 내 출장 이력 `EMPLOYEE`, 부서 출장 이력 `DEPT_MANAGER`)를 추가한다(라우트 결정 §참조). 최종 라벨/삽입 순서는 위 트리 권고안을 따르되 구현 재량.
- **출장 기안 수정 페이지·참여자 수정 다이얼로그는 별도 메뉴가 아니다**(②일반 기안 수정과 동일 — 상세/이력 경유 하위 라우트·다이얼로그). 라우트 결정이 나열한 4개 경로 중 수정 경로(`.../:draftId/edit`)는 사이드바 항목이 아닌 하위 라우트다(사이드바 신규 항목 = 3개).
- 부서 출장 이력은 `minRole: DEPT_MANAGER`로 표기 → `hasRequiredRole`가 자동 게이팅(비매니저에게 미노출). `ADMIN`은 RoleHierarchy상 자동 포함(상위 role 병기 불필요).

### 기안서 상세 페이지 — 출장 본문 렌더·참여자 수정·`[수정]` 진입 배선 (①소유 페이지에 ③ 배선 추가)

> **구현 기능:** `F732`(참여자 다이얼로그) · (배선) `F731` 진입 · (본문) `BusinessTripDraftBody`(F701 슬롯 소비) | **별도 페이지 아님**

- **출장 본문 렌더(`BusinessTripDraftBody`)**: ①의 `DraftTypeBody`의 `draft.businessTrip != null` 폴백을 실제 컴포넌트로 교체한다. `businessTrip` 슬롯(기간 `startAt~endAt`, `destination`, `purpose`, `participants[]` — ①`BusinessTripSlot` 타입 import)과 공통 `content`를 렌더. 표시용 날짜/기간 포맷은 dayjs.
- **참여자 수정(F732, 독립 다이얼로그)**: 출장 본문 내 `[참여자 수정]` 버튼(노출 = `resolveDrafterActions(draft, myEmpId).canEdit` = 기안자 본인 + UNSUBMITTED, ①판정 소비 — Open Q#3). `CirculationAddDialog` 패턴을 복제하되 **add가 아닌 전량 교체**이므로 다이얼로그 진입 시 기존 참여자(`businessTrip.participants`)를 `EmployeePicker` 초기 선택으로 **선반영**하고, `[저장]`은 현재 선택 전체를 `BUSINESS_TRIP_PARTICIPANTS_UPDATE`(최상위 배열 `number[]`, **빈 배열 불가** → 선택 0명이면 저장 비활성)로 전송. 성공 시 `approvalKeys.all` invalidate로 상세 갱신.
- **상세 `[수정]` 배선(F731 진입)**: `DrafterActions.handleEdit`에 `isBusinessTripDraft(draft)` 분기 추가 → `navigate('/approval/drafts/business-trips/${draftId}/edit')`. 노출 판정(`canEdit`)은 ①이 계산.
- **접근 권한**: 상세 페이지 자체는 ①소유(최소 요구 role `EMPLOYEE`). 참여자 다이얼로그·[수정] 버튼은 기안자 본인 + UNSUBMITTED에만 노출(①판정), 서버가 최종 판단(위반 시 403/도메인 에러 → `handleApiError` 토스트).

**계약 실측 메모:**
- **유형 판별(슬롯-null 규약, ②선례 계승):** 출장 기안 = `draft.businessTrip != null`(`isBusinessTripDraft`). `draftType` 문자열 비교 금지(백엔드 `getClass().getSimpleName()`, 스니펫 값 outdated). ①의 `isGeneralDraft`(`leave·businessTrip·sales·sourceDraftId` 전부 null)와 동형 축.
- **작성/수정 body 혼합 구조(⚠️ 평탄화 금지):** `param{title,content,approvers?}`는 ②일반 기안 body와 동일 형태이나, 출장은 그 옆에 `startAt/endAt/destination/purpose/participantIds?`(작성)·`startAt/endAt/destination/purpose`(수정, participants 제외)가 **최상위 형제**로 붙는다. `approvers` 항목 필드명은 `approverId`/`role`/`order` — 기존 `ApproverParam` 그대로.
- **날짜 정밀도 이원화:** 작성/수정 요청의 `startAt/endAt`은 **datetime**(`yyyy-MM-dd'T'HH:mm:ss`)이나, **`MY_BUSINESS_TRIP_REQUEST_HISTORY` 응답의 `startAt/endAt`은 date-only**(`yyyy-MM-dd`)다. 폼 입력(`datetime-local`, 분 단위)은 dayjs로 초를 보정해 datetime으로 전송한다.
- **이력 필터 계약 확정(`query-parameters.adoc` 실측, Open Q#2 해소):** `MY_/DEPT_BUSINESS_TRIP_REQUEST_HISTORY` 모두 `approvalStatus`·`yearMonth`(+DEPT는 `keyword`·`page`·`size`) 전부 선택(false). `approvalStatus` 전송값은 응답의 표시 문자열("결재대기")이 아니라 **enum 코드**(`UNSUBMITTED`/`WAITING`/`IN_PROGRESS`/`APPROVED`/`REJECTED`). `yearMonth`(`yyyy-MM`)는 **미입력 시 서버가 현재 월로 기본 처리** — 필터 없는 기본 화면이 "전체 이력"이 아니라 "이번 달 이력"만 보여준다는 뜻이므로, 두 이력 페이지 모두 월 선택기 기본값을 당월로 맞추고 그 사실을 안내한다(근태 `MY_ATTENDANCE_MONTHLY` yearMonth 관례와 동형).
- **참여자 = 전량 교체(add 아님):** F732 body는 최상위 `number[]`이며 필드표 근거는 "필수, 빈 배열 불가, 참여자 사원 식별 번호 목록"뿐이다. add/remove 세분 의미를 임의 부여하지 않고 **전량 교체**로 문서화(다이얼로그가 기존 참여자를 선반영해 사용자가 전체 집합을 편집).
- **응답:** 두 생성 API 모두 `201` + `{ draftId }` → 생성 후 `/approval/drafts/{draftId}` 상세 이동(②선례). 수정·참여자 교체는 `204` Empty.
- **첨부 정책(drafts 도메인, ①실측):** 확장자/용량은 게시판 동일, **기안서당 최대 10개·총 10MB**(도메인모델). 위반 에러 `FILE_001~005`. 상세 자세한 정책은 `@../docs/도메인모델.md` 참조.

## ❓ Open Questions (계약 공백 — 개발 착수 전 확인 필요)

1. **상신 시 결재선 필수 검증 위치(②Open Q#1 계승).** `BUSINESS_TRIP_DRAFT_CREATE_SUBMISSION`의 `param.approvers`는 optional로 문서화되나 도메인 규칙은 "상신=결재자 ≥1"이다. 권고안: `[임시저장으로 생성]`은 결재선 없이 허용, `[생성 후 상신]`은 결재선 ≥1 클라 사전검증(②`GeneralDraftCreatePage` 동일). 최종 판정 서버.
2. ~~이력 필터 필수여부·값 형식.~~ **해소됨(PRD 검증 단계에서 `query-parameters.adoc` 실측 반영):** `approvalStatus`·`yearMonth`(+DEPT `keyword`/`page`/`size`) 전부 선택, `approvalStatus`=enum 코드, `yearMonth` 미입력 시 서버 기본값 = 현재 월(§계약 실측 메모 참조). 남은 실행 세부(월 선택기 UI 컴포넌트 선정 등)는 구현 시 결정.
3. **참여자 교체·수정의 상태 전제.** F731 수정·F732 참여자 교체는 계약상 "기안자(EMPLOYEE)"까지만 명시되고 UNSUBMITTED 제약은 스니펫에 없다. ②수정(기안자 본인 + UNSUBMITTED)과의 일관성상 두 액션 모두 `canEdit`(기안자+UNSUBMITTED)로 노출을 게이팅하고 서버가 최종 판단하도록 가정한다. 상신 후 참여자 교체 허용 여부는 서버 반응(400/403/도메인 에러)으로 확정.
4. **부서 출장 이력의 `deptId` 도출과 ADMIN/복수 부서.** `usePrimaryDeptId`는 strict(폴백 없음)라 primary 소속이 없는 ADMIN·복수 부서 겸직 매니저는 `undefined`로 게이팅될 수 있다(근태 `DeptAttendancePage`와 동일 한계). 부서 선택 UI 도입 여부는 근태 도메인 Open Q와 함께 후속 확정.
5. **참여자 수정 노출 지점(기본안 확정 필요).** 기본안 = 상세 화면 독립 다이얼로그(F732, `CirculationAddDialog` 패턴). 수정 페이지(F731)에 참여자를 함께 노출(편의상 #3+#4 동시 호출)할지는 범위 밖으로 두되, 필요 시 후속 확정.
