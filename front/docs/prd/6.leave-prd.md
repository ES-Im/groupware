# 휴가(Leave) Frontend MVP PRD

> 이 PRD는 **휴가 신청·조회·관리** 흐름에 해당하는 기능ID만 다룬다. 두 계열이 섞여 있다:
> ① **휴가 전용 API** — `api-endpoint.md`의 "DRAFT / DOCUMENT API"(`MY_LEAVE_REQUEST_HISTORY`/`DEPT_LEAVE_REQUEST_HISTORY`/`LEAVE_DRAFT_CREATE`/`LEAVE_DRAFT_CREATE_SUBMISSION`/`LEAVE_DRAFT_UPDATE`)와 "EMP LEAVE / DEPT API"(`MY_EMP_LEAVE_SUMMARY`/`DEPT_EMP_LEAVE_SUMMARY`/`EMP_LEAVE_SUMMARY`/`EMP_LEAVE_USAGE_SUMMARY`/`DEPT_EMP_LEAVE_USAGE_SUMMARY`/`EMP_LEAVE_ADJUST_SPECIAL_GRANT_DAYS`/`EMP_LEAVE_ADJUST_COMPENSATORY_GRANT_DAYS`).
> ② **전자결재 공용 워크플로우 API**(`DRAFT_DETAIL`/`DRAFT_SUBMIT`/`DRAFT_SUBMISSION_WITHDRAWAL`/`DRAFT_CANCELLATION_CREATE`/`DRAFT_CANCELLATION_CREATE_SUBMISSION`/`DRAFT_APPROVE`/`DRAFT_REJECT`) — **휴가 기안서 컨텍스트에서만** 사용한다. 이 엔드포인트들은 일반/출장/매출 기안과 공유되므로 대부분 별도 **전자결재 도메인 PRD** 관할이나, **결재대기함**(`MY_PENDING_APPROVAL_DRAFTS`)만은 **최소 포함**한다 — 결재선에 지정된 일반 사원·타 부서 결재자가 휴가 기안 상세(F606)에 도달해 승인/반려(F610/F611)할 유일한 진입 경로이기 때문이다. 나머지 공용 문서함 3종(**결재함** `MY_ACCESSIBLE_DOCUMENTS`=내가 볼 수 있는 문서 전체 / **기안함** `MY_SUBMITTED_DRAFTS`=내가 기안한 문서 전체 / **임시저장함** `MY_UNSUBMITTED_DRAFTS`=상신 전 내 기안서)와 **문서함 요약**(`MY_DOCUMENT_BOX_SUMMARY`)·**공람**(`DRAFT_CIRCULATION_*`)·**일반/출장/매출 기안 작성**은 이 PRD 범위 밖이다.
> 공통 레이아웃 셸(헤더·사이드바·푸터)과 인증 배관은 `finish_2.shell-and-employee-view-prd.md` / `finish_1.auth-walking-skeleton-prd.md`를 참조하며 재서술하지 않는다. 전역 계약(인증·에러·페이징 `number+1`·날짜 dayjs·`ROLE_003`·파일)은 CLAUDE.md §7 `BACK-END 계약 문서` 관할이다.

## 🎯 핵심 정보

- **목적**: 사원이 휴가 기안서를 작성·상신하고 본인 신청 이력·잔여 휴가를 열람하며, 결재선 결재자가 휴가 기안을 승인/반려하고, 부서 매니저·관리자가 부서/전사 단위 휴가 신청 현황·잔여·사용률을 조회(관리자는 특별/포상 휴가 일수 조정)하는 휴가 관리 화면을 구성한다.
- **사용자**: 휴가 신청·본인 이력/잔여 열람은 `EMPLOYEE`(활성 사원) 공통. 부서 단위 이력·잔여·사용률 조회는 `DEPT_MANAGER`(같은 부서) 또는 `ADMIN`. 전사 휴가 요약·사용률·부여일수 조정은 `ADMIN` 전용. 휴가 기안 승인/반려는 해당 기안 **결재선에 지정된 결재자**(role·부서 무관, 서버 판정) — 결재자는 role/부서에 상관없이 **결재대기함**(`EMPLOYEE` 공통)을 통해 상세로 진입한다.

**권한 분기점**

- 라우트 가드(Layer 1): 미인증 → 로그인 리디렉션(auth PRD 관할). 내 휴가·작성·상세·**결재대기함** 최소 요구 role `EMPLOYEE`, 부서 휴가 관리 `DEPT_MANAGER`, 관리자 휴가 현황 `ADMIN`.
- 메뉴 노출(Layer 1): "내 휴가"·"결재대기함"은 `EMPLOYEE` 공통 노출. `hasRequiredRole(userRoles, 'DEPT_MANAGER')`일 때만 "부서 휴가 관리", `hasRequiredRole(userRoles, 'ADMIN')`일 때만 "관리자 휴가 현황" 노출. `ADMIN`은 RoleHierarchy상 하위 메뉴 자동 포함.
- 결재자 진입 경로(핵심): 휴가 기안 승인/반려 권한은 "결재선에 포함되고 현재 차례인 결재자"에게 있으며 role·부서와 무관하다. **일반 사원 결재자·타 부서 결재자는 "부서 휴가 관리"(DEPT_MANAGER 전용)로는 상세에 도달할 수 없으므로**, `EMPLOYEE` 공통 "결재대기함"(`MY_PENDING_APPROVAL_DRAFTS`)을 통해 상세로 진입한다. DEPT_MANAGER 역시 결재대기함을 사용할 수 있고, 부서 휴가 관리 이력은 결재선과 무관한 부서 전체 신청 현황 열람 용도로 병행한다.
- 서버 최종 판단:
  - 부서 조회(`DEPT_LEAVE_REQUEST_HISTORY`/`DEPT_EMP_LEAVE_SUMMARY`/`DEPT_EMP_LEAVE_USAGE_SUMMARY`)는 `DEPT_MANAGER(같은 부서)` 조건 → 타 부서 `deptId` 접근 시 **403(`ROLE_003`)**. 프론트는 세션 사용자 본인 부서만 조회 축으로 사용.
  - 휴가 기안 **승인/반려**(`DRAFT_APPROVE`/`DRAFT_REJECT`)는 "현재 결재 차례의 결재자"만 가능 → 결재선 밖 사용자·차례 아님·이미 처리 등은 서버가 최종 판정(403/도메인 에러). 프론트는 상세 응답의 결재선으로 버튼을 노출하되 최종 판단은 서버.
  - 기안 수정/상신/철회/취소기안 생성은 **기안자 본인**만 가능(서버 판정).

### 2. MVP 필수 지원 기능 — 신규 기능ID 없음(기존 셸/인증 재사용, 참조만)

모든 페이지는 기존 공통 레이아웃 셸(`finish_2.shell-and-employee-view-prd.md`)의 보호 라우트 하위에 얹힌다. 로그인·세션복원·로그아웃·본인 부서 식별(`GET /api/employees/me` / `.../belongings`)은 재서술하지 않는다. 결재선·조정 대상 사원 선택에 필요한 사원 검색 경로는 **Open Question #1** 참조(발명 금지).

### 3. MVP 이후 기능 (이번 PRD 명시적 제외)

- **전자결재 공용 문서함 3종 + 부가 API**(**결재함** `MY_ACCESSIBLE_DOCUMENTS` / **기안함** `MY_SUBMITTED_DRAFTS` / **임시저장함** `MY_UNSUBMITTED_DRAFTS` / `MY_PENDING_APPROVAL_DRAFTS_COUNT` / **문서함 요약** `MY_DOCUMENT_BOX_SUMMARY`) — **전자결재 도메인 PRD** 관할. 단 **결재대기함**(`MY_PENDING_APPROVAL_DRAFTS`)만은 휴가 결재자 상세 진입 경로 확보를 위해 이번 PRD에 최소 포함(F619) — 상세 화면은 신규로 만들지 않고 기존 휴가 기안서 상세 페이지(F606)를 재사용한다.
- **일반/출장/매출 기안 작성**(`GENERAL_DRAFT_*`/`BUSINESS_TRIP_DRAFT_*`/`SALES_DRAFT_*`) 및 **출장 참여자 수정** — 별도 도메인.
- **공람자 추가/제거/읽음**(`DRAFT_CIRCULATION_ADD`/`_REMOVE`/`_READ`) — 전자결재 도메인.
- **기안서 첨부파일 업로드/미리보기/다운로드/삭제**(`DRAFT_FILE_*`) — 상세에서 첨부 목록 표시만 다루고, 업로드/뷰어 UX는 `@docs/backend-contract/file-upload.md` 관할(Open Question #6).
- **휴가↔근태/일정 연동**(연차 승인 시 근태·`Schedule` 반영) — 백엔드 이벤트 처리이며 프론트 화면 없음.
- **연차 자동 부여(1/1 배치)·잔여 초과 사전 차단** — 서버 정책/판정.
- 테마/다크모드, 다국어(i18n), 브라우저 푸시 알림.

## 📱 메뉴 구조

```
📱 HARUON 내비게이션 (EMPLOYEE 공통 · 최소 요구 role 표기)
└── 🌴 휴가 관리 (그룹, 기존 sidebarMenuItems.ts "휴가 관리" 슬롯 재사용)
     ├── 내 휴가 — F604·F605 (+진입: 휴가 신청 F601·F602 / 상세 F606~F611) (minRole: EMPLOYEE)
     ├── 결재대기함 — F619 (+진입: 상세 F606 → 승인 F610 / 반려 F611) (minRole: EMPLOYEE)
     ├── 부서 휴가 관리 — F612·F613·F614 (minRole: DEPT_MANAGER)
     └── 관리자 휴가 현황 — F615·F616·F617·F618 (minRole: ADMIN)
```

- 기존 `src/shared/components/sidebarMenuItems.ts`의 "휴가 관리" 그룹 placeholder(`내 휴가 요약`/`부서 휴가 관리`)를 실 라우트로 승격(`implemented: true` + `to`)하고, "내 휴가 요약"은 잔여+이력을 함께 다루므로 라벨을 **"내 휴가"**로 조정한다. "관리자 휴가 현황"(`minRole: 'ADMIN'`)·"결재대기함"(`minRole: 'EMPLOYEE'`)은 같은 그룹에 **신규 슬롯 추가** — 기존 placeholder에는 없으므로 추가 필요. **도메인 밖 신규 메뉴 발명 아님.**
- **결재대기함 위치 주의**: `MY_PENDING_APPROVAL_DRAFTS`는 본래 전자결재 도메인 문서함이나, 휴가 결재자 상세 진입 확보를 위해 이번엔 "휴가 관리" 그룹에 최소 노출한다. 사이드바 구성은 임시적이므로(사용자 확인), 추후 전자결재 도메인 PRD 착수 시 "전자결재" 그룹으로 이관될 수 있다 — 그때는 같은 라우트를 전자결재 그룹에서 참조하고 휴가 그룹 슬롯을 제거한다.
- "결재대기함"·"내 휴가"는 `EMPLOYEE` 공통, "부서 휴가 관리"는 `DEPT_MANAGER`에게만, "관리자 휴가 현황"은 `ADMIN`에게만 노출. `ADMIN`은 RoleHierarchy상 전 메뉴 자동 포함(별도 ADMIN 항목 불필요).
- 휴가 기안서 **작성/수정·상세**는 별도 메뉴가 아니라 내 휴가/부서 휴가 관리에서 진입하는 하위 라우트다.

**공통 enum · 표시 규칙(스니펫/도메인모델/소스 실측):**
- **`LeaveType`(소스 `LeaveType.java`):** `ANNUAL`(연차) · `HOURLY`(공휴일※) · `SICK`(병가) · `OFFICIAL`(공가) · `COMPENSATORY`(대체휴무) · `SPECIAL`(특별휴가). ※`HOURLY`의 description이 "공휴일"로 되어 있어 의미 모호 → Open Question #3.
- **`ApprovalStatus`(도메인모델.md):** `UNSUBMITTED`(임시저장/미상신) · `WAITING`(결재대기) · `IN_PROGRESS`(결재진행중) · `APPROVED`(결재완료) · `REJECTED`(결재반려). 목록 응답의 `approvalStatus`는 **표시명 문자열**(예 "결재대기")로 내려오고, 필터 query는 **enum 코드**로 보낸다.
- **날짜 포맷:** 기안 생성/상세의 `startAt`/`endAt`은 `yyyy-MM-dd'T'HH:mm:ss`(일시), 신청 이력 목록의 `startAt`/`endAt`은 `yyyy-MM-dd`(일자). 표기·파싱은 전부 dayjs.
- **휴가 일수:** `requestedLeaveDays`(예 1.0=연차 1일, 0.5=반차)·`*GrantDays`·`*UsedDays`는 소수 1자리 number. `reservedHours`(상세 `leave`)는 예약 시간 수(연가 1시간 단위 규칙).

## ❓ Open Questions (계약 공백 — 개발 착수 전 확인 필요)

1. **결재선 결재자 사원 검색 경로.** 휴가 기안 작성 시 `approvers[].approverId`를 지정하려면 사원 검색 UI가 필요하다. `EMPS_FOR_MANAGEMENT`(HR/DEPT_MANAGER 전용)·`NEW_EMP_LIST`(HR 전용)는 일반 사원이 못 쓴다. `DEPT_MEMBERS`(`/api/departments/{deptId}/members`, `EMPLOYEE` 가능)·`DEPTS`로 후보를 조회하는 방식이 유일해 보이는데, **일반 사원의 결재자 후보 조회 표준 경로**를 확정 필요. (관리자 휴가 현황의 조정 대상 `empId`는 요약 응답 `empId` 보강으로 해소됨 — Open Question #5 참조.)
2. **잔여 초과 사전 검증 여부.** 도메인상 사용일수 차감은 결재완료 이후이고 초과는 서버가 판정한다. 프론트는 잔여만 표시하고 상신은 서버 판정에 맡기는 것으로 가정 — 신청 단계 사전 경고 UX가 필요한지 확인.
3. **`HOURLY` 휴가 유형 라벨 모호.** enum description이 "공휴일"인데 "연가 1시간 단위 사용"(도메인모델.md) 규칙과 함께 보면 시간 단위 연차를 의미할 여지가 있다. 화면 표기 라벨과 `reservedHours` 표기 규칙(“n시간”) 확정 필요.
4. **상세 페이지 액션 버튼 노출 판정 기준.** "현재 내 결재 차례"는 상세 응답(`drafter.empId`, `approvers[].empId/order/approvedAt/rejectedAt`)으로 프론트 도출 가능하나(본인이 결재선에 있고 이전 order 전부 처리·본인 미처리), 최종 판단은 서버다. 취소 기안 노출 조건(원본 `APPROVED` + `cancellationDraftId==null`)도 이 필드로 도출 가정 — 규칙 확정 필요.
5. **(해결됨) 부서/전사 휴가 요약 응답에 `empId`가 없던 문제.** `DEPT_EMP_LEAVE_SUMMARY`·`EMP_LEAVE_SUMMARY` 응답 `content[]`에 `empNo`/`empName`만 있고 `empId`가 없어, path에 `empId`를 요구하는 `EMP_LEAVE_ADJUST_SPECIAL/COMPENSATORY_GRANT_DAYS`를 요약 표에서 곧바로 호출할 수 없던 계약 공백이었다(근태 PRD의 `attendanceId` 누락과 동일 패턴). 사용자 승인 하에 **백엔드를 근태 선례와 동일하게 보강**했다: `LeaveSummaryAndEmpInfoResponse`에 `empId:Long` 추가 + QueryDSL 프로젝션(`LeaveSummaryListFlat`)에 `emp.id` 반영 + REST Docs 테스트/스니펫 재생성 + 통합 테스트 assertion 추가(전부 통과 확인). `DEPT_EMP_LEAVE_SUMMARY`/`EMP_LEAVE_SUMMARY` 응답 `content[]`에 이제 `empId:number`가 맨 앞 필드로 포함된다. F615 요약 행에서 받은 `empId`를 F617/F618 path에 그대로 사용하면 되며, Open Question #1의 "조정 대상 사원 검색" 필요성도 해소되었다.
6. **휴가 기안 첨부파일 범위.** 상세 응답 `files[]`는 표시하나, 작성/상세에서 첨부 업로드(`DRAFT_FILE_UPLOAD`)·미리보기/다운로드(`DRAFT_FILE_*`)를 이번 범위에 포함할지, 정책은 `@docs/backend-contract/file-upload.md` 참조로 위임할지 확정 필요.
7. **결재대기함의 휴가 외 기안 유형 처리.** `MY_PENDING_APPROVAL_DRAFTS`는 공용 문서함이라 휴가·일반·출장·매출 기안이 모두 섞여 온다. 목록 응답에는 `draftType`이 없어(제목/기안자만) 클릭 전 유형 식별이 불가하다. 이번 휴가 PRD 범위에선 상세 진입 후 `DRAFT_DETAIL.draftType`으로 분기해 **휴가 기안만 상세 렌더**하고, 그 외 유형은 "전자결재 도메인에서 처리 예정" 안내로 폴백하는 것으로 가정. 목록 단계 유형 필터/뱃지 필요 여부, 폴백 UX(비활성/안내 페이지)를 확정 필요. (전자결재 도메인 PRD 착수 시 통합 해소.)
8. **(해결됨) 결재선 결재자의 상세 진입 경로 부재.** 당초 상세 진입이 "내 휴가(본인)"·"부서 휴가 관리(DEPT_MANAGER 전용)" 두 경로뿐이라, 결재선에 지정된 **일반 사원 결재자·타 부서 결재자**가 휴가 기안 상세(F606)에 도달해 승인/반려(F610/F611)할 방법이 없던 구조적 결함이었다. 사용자 결정에 따라 전자결재 공용 문서함 4종 중 **결재대기함**(`MY_PENDING_APPROVAL_DRAFTS`)만 이 PRD에 최소 포함(F619, `EMPLOYEE` 공통)해, role·부서와 무관하게 결재자가 상세로 진입하는 표준 경로를 확보했다. 상세 화면은 신규 생성 없이 기존 F606 상세 페이지를 재사용한다. 잔여 세부(혼재 유형 처리)는 Open Question #7로 이관.
