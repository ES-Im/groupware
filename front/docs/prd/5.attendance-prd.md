# 근태(Attendance) Frontend MVP PRD

> 이 PRD는 `api-endpoint.md`의 **"ATTENDANCE API"** 섹션 8개 기능ID만 다룬다:
> 본인 근태 4개(`MY_ATTENDANCE_CHECK_IN`/`MY_ATTENDANCE_CHECK_OUT`/`MY_ATTENDANCE_MONTHLY`/`MY_ATTENDANCE_MONTHLY_SUMMARY`) + 부서 근태 4개(`DEPT_ATTENDANCE_MONTHLY`/`DEPT_ATTENDANCE_PENDING`/`DEPT_ATTENDANCE_UPDATE`/`DEPT_ATTENDANCE_APPROVE`).
> **휴가(`*_LEAVE_*`)·출장(`*_BUSINESS_TRIP_*`)·기안/정정(`*_DRAFT_*`)은 근태와 인접하나 별도 도메인**(전자결재/휴가 PRD 관할)이라 이 PRD 범위 밖이다. 근태 목록의 `draftId`(연동 기안서)는 표시만 하고, 정정 신청 화면은 여기서 정의하지 않는다.
> 공통 레이아웃 셸(헤더·사이드바·푸터)과 인증 배관은 `finish_2.shell-and-employee-view-prd.md` / `finish_1.auth-walking-skeleton-prd.md`를 참조하며 재서술하지 않는다. 전역 계약(인증·에러·페이징·날짜·`ROLE_003`)은 CLAUDE.md §7 `BACK-END 계약 문서` 관할이다.

---

## 🎯 핵심 정보

- **목적**: 사원이 출·퇴근을 기록하고 본인 월별 근태·요약을 열람하며, 부서 매니저가 부서원 월별 근태를 조회·수정·승인(확정)하는 근태 관리 화면을 구성한다.
- **사용자**: 출퇴근·본인 근태 열람은 `EMPLOYEE`(본인) 전체 공통. 부서 근태 조회·수정·승인은 `DEPT_MANAGER`(같은 부서) 또는 `ADMIN`.

## 🚶 사용자 여정

```
[비인증/세션복원 흐름] — auth-walking-skeleton-prd.md 관할(재서술 안 함)

[사이드바 "근태 > 내 근태"] → 내 근태 페이지
  ├ 상단: 오늘 출근/퇴근 상태 + [출근] / [퇴근] 버튼(오늘 근태 기록에 따라 활성/비활성)
  ├ 월 선택(yyyy-MM, 기본=현재 월) + 근태 상태 필터
  ├ 월별 요약 카드(승인완료/승인대기/전체/초과근무분)
  └ 월별 근태 표(일자·상태·출퇴근시각·승인여부) + 페이징

[사이드바 "근태 > 부서 근태 승인"] (DEPT_MANAGER 이상만 노출) → 부서 근태 관리 페이지
  ├ 탭① 월별 근태: 부서원 검색(keyword)·월 선택·상태 필터 + 사원별 요약/상세 + 페이징
  │     └ (미승인 행) 근태 수정 다이얼로그 → 성공 → 목록 재조회
  └ 탭② 승인 대기: 승인 대기 근태 목록 + 페이징
        └ 행 [승인] → 성공 → 목록 재조회 / [수정] → 수정 다이얼로그
```

**권한 분기점**

- 라우트 가드(Layer 1): 미인증 → 로그인 리디렉션(auth PRD 관할). 내 근태 페이지 최소 요구 role `EMPLOYEE`, 부서 근태 관리 페이지 최소 요구 role `DEPT_MANAGER`.
- 메뉴 노출(Layer 1): `hasRequiredRole(userRoles, 'DEPT_MANAGER')` 참일 때만 "부서 근태 승인" 메뉴·페이지 진입 노출(`EMPLOYEE`에게는 메뉴 자체가 보이지 않음, `ADMIN`은 계층상 자동 포함).
- 서버 최종 판단: 부서 근태 4개 엔드포인트는 `DEPT_MANAGER(같은 부서)` 조건이라 **타 부서 `deptId`/`attendanceId` 접근 시 403(`ROLE_003`)** 이 최종 판단한다. 프론트는 "같은 부서" 여부를 판정하지 않고, 세션 사용자 본인 부서(`deptId`)만 조회 축으로 사용하며 403은 권한 부족 UX로 처리한다.

### 2. MVP 필수 지원 기능 — 신규 기능ID 없음(기존 셸/인증 재사용, 참조만)

두 페이지 모두 기존 공통 레이아웃 셸(`finish_2.shell-and-employee-view-prd.md`)의 보호 라우트 하위에 얹힌다. 로그인·세션복원·로그아웃·본인 부서 식별(`GET /api/employees/me` 소속정보)은 재서술하지 않는다.

### 3. MVP 이후 기능 (이번 PRD 명시적 제외)

- **근태 정정/이의 신청 화면** — 정정은 기안서(`*_DRAFT_*`, `draftId` 연동) 경로이며 전자결재 도메인 PRD 담당. 계약상 근태 도메인에는 사원 발起 정정 신청 엔드포인트가 없다.
- **휴가/연차·출장 신청·잔여 휴가**(`*_LEAVE_*`, `*_BUSINESS_TRIP_*`) — 별도 도메인 PRD 담당.
- **근태 통계/차트 대시보드** — 계약은 월별 목록·요약 수치만 제공. Recharts 시각화는 MVP 이후.
- **관리자(ADMIN) 전용 전사 근태 조회** — ATTENDANCE API에는 부서 단위 조회만 존재(전사 조회 엔드포인트 없음). ADMIN은 계층상 부서 근태 화면을 그대로 사용.
- 테마/다크모드, 다국어(i18n), 브라우저 푸시 알림.

## 📱 메뉴 구조

```
📱 HARUON 내비게이션 (EMPLOYEE 공통 · 최소 요구 role 표기)
└── ⏰ 근태 (그룹, 기존 sidebarMenuItems.ts 슬롯 재사용)
     ├── 내 근태 — F301·F302·F303·F304 (minRole: EMPLOYEE)
     └── 부서 근태 승인 — F305·F306·F307·F308 (minRole: DEPT_MANAGER)
```

- 기존 `src/shared/components/sidebarMenuItems.ts`의 "근태" 그룹에 이미 선언된 placeholder 두 항목(`내 근태`/`부서 근태 승인`)을 실 라우트로 승격(`implemented: true` + `to`)한다. **신규 메뉴 발명 아님.**
- "부서 근태 승인"은 `minRole: 'DEPT_MANAGER'`로 게이팅되어 일반 `EMPLOYEE`에게는 미노출, `ADMIN`은 RoleHierarchy상 자동 노출된다(별도 ADMIN 항목 불필요).
- 근태 수정/승인은 별도 메뉴가 아니라 부서 근태 관리 페이지 내부의 행 액션(다이얼로그·버튼)으로 노출한다.

## 📄 페이지별 상세 기능

### 내 근태 페이지

> **구현 기능:** `F301`, `F302`, `F303`, `F304` | **메뉴 위치:** ⏰ 근태 > 내 근태

| 항목 | 내용 |
|---|---|
| **역할** | 본인 출·퇴근 기록과 월별 근태·요약 열람. 하루 근무의 시작/종료 액션 진입점 |
| **진입 경로** | 사이드바 "근태 > 내 근태" |
| **접근 권한** | 최소 요구 role: `EMPLOYEE`(본인, `MY_ATTENDANCE_*`) / 서버 최종 판단: 없음(본인 스코프 `/me`) |
| **사용자 행동** | [출근]/[퇴근] 버튼 클릭, 조회 월(yyyy-MM) 변경, 근태 상태 필터 선택, 페이지 이동 |
| **주요 기능** | • **출근**(F301)·**퇴근**(F302) 버튼 — 오늘(현재 월) 근태 기록으로 상태 도출: 오늘 기록 없음→출근 활성/퇴근 비활성, 출근만 있음(endAt 없음)→퇴근 활성/출근 비활성, 출퇴근 완료→둘 다 비활성(개념적. 세부 판정 규칙은 Open Question 참조) • 월별 요약 카드(F304: 승인완료/승인대기/전체/초과근무분) • 월별 근태 표(F303: 일자·상태 배지·출퇴근시각·승인여부, dayjs 포맷) + 페이징(number+1) |
| **다음 이동** | 출근/퇴근 성공(204) → 월별 목록·요약 invalidate + 성공 토스트, 규칙 위반(예: 미출근 상태 퇴근, 중복 출근) → 에러 토스트(sonner), 조회 실패 → 에러 토스트 |

### 부서 근태 관리 페이지

> **구현 기능:** `F305`, `F306`, `F307`, `F308` | **메뉴 위치:** ⏰ 근태 > 부서 근태 승인

| 항목 | 내용 |
|---|---|
| **역할** | 부서 매니저가 본인 부서원의 월별 근태를 조회하고, 미승인 근태의 시각을 수정하거나 승인(확정)하는 관리 화면 |
| **진입 경로** | 사이드바 "근태 > 부서 근태 승인"(DEPT_MANAGER 이상 노출) |
| **접근 권한** | 최소 요구 role: `DEPT_MANAGER`(`DEPT_ATTENDANCE_*`) / 서버 최종 판단: 같은 부서 여부는 **403(`ROLE_003`)** — 타 부서 `deptId`/`attendanceId` 접근 시 권한 부족 UX(재발급 금지) |
| **사용자 행동** | 탭 전환(월별 근태 ↔ 승인 대기), 부서원 이름 검색, 조회 월·상태 필터, 페이지 이동, 미승인 행 [수정]/[승인] 클릭 → 다이얼로그 입력·제출 |
| **주요 기능** | • 부서 월별 근태 조회(F305: 사원정보+요약+상세 배열, keyword/yearMonth/status/page/size) • 승인 대기 근태 조회(F306: 사원정보+단건 근태, page/size) • 근태 수정 다이얼로그(F307: RHF+zod — startAt·endAt 중 최소 1개 HH:mm:ss + editReason 필수 100자 이하, editedAt=현재시각 ISO, targetEmpId 동봉) • 근태 승인(F308: targetEmpId+approvedAt=현재시각 ISO) — 이미 승인/당일 건은 버튼 비활성 또는 서버 에러 처리 |
| **다음 이동** | 수정/승인 성공(204) → 해당 탭 목록 invalidate + 성공 토스트, 검증 실패 → 폼 필드 에러, 이미 승인/당일 승인/승인건 수정 등 규칙 위반 → 에러 토스트(sonner), 타 부서 접근 403(`ROLE_003`) → 권한 부족 안내 |

> **참고**: 로그인/회원가입/승인 대기, 공통 셸(헤더·사이드바·푸터), 사원 상세/내 정보는 각각 `finish_1.auth-walking-skeleton-prd.md`/`finish_2.shell-and-employee-view-prd.md` 관할이며 이 PRD에서 재정의하지 않는다.

| 부서 근태 관리(월별) | attendance | `DEPT_ATTENDANCE_MONTHLY` | `Page<DeptAttendanceRow>{ content[]{ empInfo{empId:number, empNo, empName, deptName, positionName}, summary{approved/pending/total/overtimeMinutes}, attendanceInfo: AttendanceItem[] } }` + 페이징 메타 | path `deptId`(본인 부서) + query keyword/yearMonth/status/page/size optional. `attendanceInfo`는 **배열** |
| 부서 근태 관리(승인대기) | attendance | `DEPT_ATTENDANCE_PENDING` | `Page<DeptPendingRow>{ content[]{ empInfo{empId, empNo, empName, deptName, positionName}, attendanceInfo: AttendanceItem(단건 객체) } }` + 페이징 메타 | path `deptId` + query page/size only. `attendanceInfo`는 **단일 객체**(월별과 형태 다름 — 타입 분리) |
| 부서 근태 관리(수정) | attendance | `DEPT_ATTENDANCE_UPDATE` | `DeptAttendanceUpdateRequest{ targetEmpId:number(required), startAt:"HH:mm:ss"?, endAt:"HH:mm:ss"?, editedAt:ISO_DATE_TIME(required), editReason:string(required,≤100) }` | path `attendanceId` — F305/F306 목록 응답의 `attendanceInfo[].attendanceId`(또는 단건 `attendanceInfo.attendanceId`)를 그대로 사용. startAt·endAt 중 최소 1개 필수(zod refine). `204` Empty |
| 부서 근태 관리(승인) | attendance | `DEPT_ATTENDANCE_APPROVE` | query `targetEmpId:number(required)`, `approvedAt:ISO_DATE_TIME(required, 예 2026-04-30T09:00:00)` | path `attendanceId` — F306 목록 응답의 `attendanceInfo.attendanceId` 사용. body 없음. `204` Empty |

**공통 타입 `AttendanceItem`(스니펫 재실측 — `attendanceId` 추가됨):** `{ attendanceId:number, attendanceStatus, attendanceDate:"yyyy-MM-dd", startAt:"HH:mm:ss"\|null, endAt:"HH:mm:ss"\|null, isApproved:boolean, draftId:number\|null }`.
**`AttendanceStatus` enum(도메인모델 실측):** `NORMAL`(정상) · `LATE_EARLY`(지각/조퇴) · `HALF_DAY_LEAVE`(반차) · `ALL_DAY_LEAVE`(연차) · `SICK_LEAVE`(병가) · `ABSENT`(결근). 시간 필수 상태=`NORMAL`/`LATE_EARLY`/`HALF_DAY_LEAVE`, 시간 없음=`ALL_DAY_LEAVE`/`SICK_LEAVE`/`ABSENT`(startAt/endAt null 가능).

## ❓ Open Questions (계약 공백 — 개발 착수 전 확인 필요)

1. **(해결됨) 부서 근태 수정·승인에 필요한 `attendanceId`가 목록 응답에 없던 문제.** `DEPT_ATTENDANCE_UPDATE`/`DEPT_ATTENDANCE_APPROVE`가 path에 요구하는 `attendanceId`가 `DEPT_ATTENDANCE_MONTHLY`·`DEPT_ATTENDANCE_PENDING` 응답에 없던 계약 공백이었다. 백엔드 확인 결과 실제 코드(`AttendanceInfoResponse`, `AttendanceQueryRepositoryAdapter`)에 필드 자체가 누락되어 있었음을 확인, 사용자 승인 하에 **백엔드에 `attendanceId` 필드를 추가**(QueryDSL 프로젝션에 `qAttendance.id` 반영 + REST Docs 스니펫 재생성 + 관련 백엔드 테스트 갱신, 전부 통과 확인)했다. `MY_ATTENDANCE_MONTHLY`/`DEPT_ATTENDANCE_MONTHLY`/`DEPT_ATTENDANCE_PENDING` 응답의 `attendanceInfo`(또는 `content[]`)에 이제 `attendanceId:number`가 포함된다. F307/F308은 목록에서 받은 `attendanceId`를 그대로 path에 사용하면 된다.
2. **부서 `deptId` 출처 확정.** `DEPT_ATTENDANCE_MONTHLY`/`PENDING`의 path `deptId`는 "본인 부서"로 가정했다. 매니저가 복수 부서를 관리하는 경우 부서 선택 UI가 필요한지, `GET /api/employees/me/belongings`의 어떤 필드를 deptId로 쓰는지 확인 필요(auth/emp PRD 계약과 정합 확인).
3. **(해결됨) 오늘 출근/퇴근 버튼 상태 판정.** 당일 근태 존재 여부를 알려주는 단건 엔드포인트가 없어 `MY_ATTENDANCE_MONTHLY`(현재 월)에서 오늘 일자 레코드로 도출하는 방식을 제안했었다. 화면 표시용 목록 쿼리(사용자 필터/페이지에 따라 바뀜)를 그대로 재사용하면 페이지네이션·상태 필터·다른 달 조회 시 오늘 레코드가 응답에서 빠져 오판(중복 출근 위험)하는 문제가 있어, **프론트에서 필터 없는 전용 쿼리(파라미터 고정: 현재월·status 없음·page=0·size=100)로 오늘 출퇴근 상태만 별도 판정**하도록 해결했다(T2.3, `MyAttendancePage.tsx`의 `todayAttendanceQuery`). 백엔드 계약 변경 없음.
4. **초과근무(overtimeMinutes) 표기 단위.** 분 단위 정수 → 화면에서 "n시간 m분" 변환 표기로 가정. 반올림/표기 규칙 확인 권장.
