# 쪽지함(Message) Frontend MVP PRD

> 이 PRD는 쪽지 도메인 — **4개 메일박스(받은/보낸/임시보관/휴지통) 목록·검색·페이징, 쪽지 상세 열람, 새 쪽지 작성(즉시 발송·임시저장), 임시 쪽지 편집·발송, 읽음/휴지통/복구/완전삭제 생명주기, 첨부파일 업로드·삭제·미리보기/다운로드** — 만 다룬다.
>
> **계약 원천 이원화(중요):** 쪽지 **조회(GET) 7종**은 `api-endpoint.md` 인덱스에 **등재돼 있지 않고** `back/build/generated-snippets`에도 폴더가 없다(REST Docs 미작성 — `MessageQueryApiDocsTest`가 존재하지 않음). 따라서 조회 API의 응답 필드는 팀리드가 **컨트롤러/DTO 소스**(`back/.../adapter/webapi/message/MessageQueryApi.java` + `Messages/MessageDetail/MessageCount/FileList` DTO record)를 직접 읽어 확정한 값을 ground truth로 삼는다(추측 아님). 반면 **명령(Command) API**(임시저장/발송/삭제/휴지통/파일 등)는 `api-endpoint.md`(166~178, 237·243·228~229행)의 기능ID와 `back/build/generated-snippets/<기능ID>/`가 정식 원천이다. → 조회 API의 계약 문서 보강 필요는 **§❓ Open Questions #1** 에 플래그한다.
>
> 전역 계약(인증·부팅 시 `reissue`·에러 `ApiError`/`code` 분기·`withCredentials`·날짜 dayjs·페이징 `Page` 구조/`number` 0-based)은 CLAUDE.md §7 `BACK-END 계약 문서` 관할이며 재서술하지 않는다. 공통 인증 배관(토큰 인메모리·부팅 reissue·`GET /api/employees/me`)·`apiError` 유틸·페이징 파서 등 기존 `src/shared/**` 자산을 **소비**한다.

## 🎯 핵심 정보

- **목적**: 사원이 사내 쪽지를 4개 메일박스로 관리한다 — 받은/보낸/임시보관/휴지통을 탭으로 탐색·검색·페이징하고, 쪽지를 열람하며, 수신자를 골라 새 쪽지를 즉시 발송하거나 임시저장했다가 다시 이어 작성·발송하고, 첨부파일을 올리고, 읽음/휴지통 이동/복구/완전삭제 생명주기를 수행한다.
- **사용자**: 전 기능 최소 요구 role `EMPLOYEE`(활성 사원). 관리자 전용 기능 없음. **쪽지 단위 세부 권한(작성자/발신자/수신자 소유 여부)은 role이 아니라 사원-쪽지 관계로 서버가 최종 판정**한다(비소유 접근 → 일반 403 또는 `MESSAGE_NOT_FOUND_EXCEPTION` 404). 부서 스코프 로직이 없으므로 `ROLE_003`은 이 도메인에 해당하지 않는다.

**권한 분기점**

- **라우트 성격(Layer 1)**: `/messages`·`/messages/:box`는 메인 인증 셸(`LayoutShell`) 하위 보호 라우트다. 전 기능 최소 요구 role `EMPLOYEE`. 다른 EMPLOYEE 레벨 도메인(게시판·근태 내 근태 등)과 동일하게 **`ProtectedRoute`(인증 가드)만으로 충분**하다(RoleGuard 불필요). role 분기 없음.
- **메뉴 노출**: 사이드바에 **`쪽지함` 단독 최상위 항목**(Mail 아이콘, `EMPLOYEE`)으로 노출한다. 기존 `게시판/쪽지` 그룹에서 분리한다(§📱).
- **서버 최종 판단(role 아닌 소유 관계)**: 상세·읽음·휴지통·복구·삭제·임시편집·파일 액션은 모두 **해당 쪽지의 작성자/발신자/수신자**만 가능 → 비소유 접근 시 서버 일반 403 또는 `MESSAGE_NOT_FOUND_EXCEPTION`(404) → 권한 부족/not-found UX(재발급 금지, `code`로 분기하되 처리 로직은 상태코드 기반). 즉시 발송은 `receiverIds` 누락 시 서버 `MESSAGE_RECEIVER_REQUIRED_EXCEPTION` → 폼 에러 UX.

### 3. MVP 이후 기능 / 범위 외 (이번 PRD 명시적 제외)

- **전달/재전송(forward) 전용 기능**: 백엔드에 "전달" 엔드포인트가 **없다.** 답장과 동일한 작성 뷰 프리필로 흉내낼 수는 있으나(본문 복사·수신자 비움) 사용자 요구(요구사항 3, "실제 API 없는 부분은 과감히 버릴 것")에 따라 **(결정, 2026-07-10) MVP 제외**로 확정. 후속 필요 시 답장과 동일 메커니즘으로 추가.
- **일괄 선택 후 벌크 액션(다중 선택 삭제)**: 벌크 삭제 전용 API가 없어 개별 액션을 순차 호출해야 한다 → **(결정, 2026-07-10) 목록 선택 체크박스 자체를 노출하지 않고 행별 개별 삭제 버튼만 제공**(검증자 권장, MVP 단순화). 벌크 선택 UI는 범위 외.
- **쪽지 실시간 수신 알림(푸시/뱃지 실시간 갱신)**: 쪽지는 STOMP 계약이 없다(채팅과 별개) → 실시간 없음. 안읽음 건수는 `mailboxes/counts` 재조회로만 갱신.
- **테마/다크모드·다국어(i18n)·브라우저 푸시 알림**: 전 도메인 공통 제외.

## 🧩 첨부파일 2단계 업로드 흐름 (핵심 구현 제약)

`MESSAGE_FILE_UPLOAD`(`PATCH /api/messages/{messageId}/files`)는 **messageId가 이미 존재해야** 호출 가능하다. 즉 새 쪽지에 첨부하려면 먼저 쪽지를 만들어 messageId를 확보한 뒤 파일을 올려야 한다. 화면은 파일을 **로컬 스테이징**했다가 다음 순서로 처리한다.

- **첨부 있는 새 쪽지 발송(권장 orchestration)**: 파일을 로컬 스테이징 → **① `MESSAGE_DRAFT_CREATE`**(messageId 확보) → **② `MESSAGE_FILE_UPLOAD`**(스테이징 파일 업로드) → **③ `MESSAGE_DRAFT_SEND`**(발송). `MESSAGE_SEND`를 직접 쓰면 수신자에게 **첨부 전에 즉시 전달**되는 순서 문제가 생기므로, **첨부가 있으면 draft-first 경로**를 택한다.
- **첨부 있는 임시저장**: `MESSAGE_DRAFT_CREATE` → `MESSAGE_FILE_UPLOAD`(→ 임시보관 유지).
- **첨부 없는 즉시 발송**: `MESSAGE_SEND` 단건.
- **임시 쪽지 편집**: messageId가 이미 있으므로 `MESSAGE_FILE_UPLOAD`/`MESSAGE_FILE_DELETE`를 즉시 호출 가능. 발송은 `MESSAGE_DRAFT_SEND`.

> 위 draft-first orchestration(발송 직전 draft 경유)의 채택 여부는 **Open Q#6**로 남긴다(대안: `MESSAGE_SEND` 후 업로드). 화면 카피는 "전송" 하나로 노출하고 내부 순서는 첨부 유무로 분기한다.

F1501~F1504·F1510 → 쪽지함 페이지 ✅ / F1505·F1511·F1512·F1513·F1514·F1519·F1522 → 쪽지 상세 뷰 ✅ / F1506·F1507·F1515·F1516·F1517·F1518·F1519·F1520·F1521 → 쪽지 작성 뷰 ✅. 모든 관련 페이지 실존(단일 `/messages/:box` 라우트 내 3개 뷰).

**🔍 2단계: 메뉴 → 페이지**
사이드바 `쪽지함`(신규 최상위) → `/messages`(→received) → 쪽지함 페이지 존재 ✅. 4개 탭·상세·작성 뷰가 모두 페이지 상세에 정의 ✅. 게시판 그룹에서 쪽지함 분리 명시 ✅.

**🔍 3단계: 페이지 → 역참조**
3개 뷰의 모든 F ID가 기능 명세에 정의 ✅. 전 뷰 진입 경로·접근 권한 항목 존재 ✅. 목록→상세/작성, 상세→답장(작성), 작성→목록 도달 경로 명시 ✅.

**🔍 4단계: 계약 근거**
명령 F(F1506·F1507·F1512~F1518·F1520·F1521·F1522) → `api-endpoint.md` MESSAGE/FILE 기능ID 실존 확인 ✅. 조회 F(F1501~F1505·F1510·F1519) → 인덱스·스니펫 부재를 명시하고 컨트롤러/DTO 소스 근거로 표기(발명 아님, Open Q#1) ✅. 근거 없는 발명 기능 없음(전달·벌크·실시간은 "범위 외" 격리) ✅.

**🔍 5단계: 누락/고아**
고아 기능·페이지·메뉴 없음 ✅. 전달/벌크삭제/실시간알림은 계약 부재로 "범위 외" 명시(누락 아님) ✅. EmployeePicker·답장 프리필은 순수 UI 재사용(기능ID 없음)으로 지원 기능에 분리 ✅. 잔여 계약 공백(조회 Docs·EmployeePicker 위치·사이드바 배지·전달·벌크·첨부 orchestration)은 Open Q#1~#6로 격리 ✅.

**결과: 5단계 전부 통과. 쪽지 도메인 F1501~F1522 개발 착수 가능. Open Questions는 전부 비블로킹(#1 조회 Docs 보강·#6 첨부 orchestration은 구현 시 확인 권장).**
