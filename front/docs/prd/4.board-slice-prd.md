# 게시판(Board) 세로 슬라이스 Frontend MVP PRD

> 이 PRD는 `api-endpoint.md`의 **"BOARD / MESSAGE / CHAT API"** 섹션 중 게시판·댓글·게시판 첨부 기능ID(`BOARD_LIST`/`BOARD_DETAIL`/`BOARD_REGISTER`/`BOARD_PUBLISH`/`BOARD_UPDATE`/`BOARD_EDIT_MODE`/`BOARD_DRAFTS`/`BOARD_FILES`/`BOARD_FILE_UPLOAD`/`BOARD_FILE_DOWNLOAD`/`BOARD_FILE_PREVIEW`/`BOARD_FILE_DELETE`/`BOARD_COMMENTS`/`COMMENT_REGISTER`/`COMMENT_REPLY`/`COMMENT_UPDATE`/`COMMENT_DELETE`)와, 카테고리 필터 소스인 `CATEGORY_LIST`만 다룬다.
> 카테고리 **관리**(`CATEGORY_MANAGEMENT`/`CATEGORY_REGISTER`/`CATEGORY_UPDATE_NAME`/`CATEGORY_ACTIVATE`/`CATEGORY_DEACTIVATE`, ADMIN)와 쪽지·채팅은 같은 섹션이지만 별도 도메인이라 이 PRD 범위 밖이다.
> 공통 레이아웃 셸·인증 배관·에러/페이징/날짜/파일 전역 계약은 `finish_1.auth-walking-skeleton-prd.md` / `finish_2.shell-and-employee-view-prd.md` 및 CLAUDE.md §7 `BACK-END 계약 문서`(`@docs/backend-contract/`) 관할이며 재서술하지 않는다.

## 🎯 핵심 정보

- **목적**: 카테고리별 게시글 목록(페이징) → 상세(첨부 다운로드/미리보기·댓글) → 작성/수정(임시저장·발행·첨부 업로드) → 삭제(댓글 soft delete)로 이어지는 게시판 세로 슬라이스를 구성하고, 그 과정에서 **페이징 UI 표준**과 **파일 첨부 업로드/다운로드 표준**을 최초 확정한다.
- **사용자**: 열람·작성·댓글은 로그인한 모든 사원(`EMPLOYEE` 공통, 작성/댓글은 서버가 **활성 사원** 판정). 게시글 수정/발행/첨부관리는 **게시글 작성자 또는 ADMIN**, 댓글 수정/삭제는 **댓글 작성자**(서버 최종 판단).

```
[비인증/세션복원 흐름] — finish_1.auth-walking-skeleton-prd.md 관할(재서술 안 함)

[사이드바 "게시판"] → 게시판 목록 페이지
  ├ 카테고리 선택(노출 카테고리 목록에서) / 제목 keyword 검색 / 페이징(이전·다음·페이지번호·total)
  ├ "글쓰기" 버튼 → 게시글 작성 페이지
  ├ "임시저장함" 진입 → 내 임시저장 목록(본인만)
  └ 게시글 행/카드 클릭 → 게시글 상세 페이지
        ├ 제목·본문(longtext)·작성자·발행/수정시각·조회수·좋아요수·댓글수 확인(진입 시 서버가 조회수 증가)
        ├ 첨부목록: 이미지 → 인라인 미리보기(blob), 그 외 → 다운로드
        ├ 댓글: 목록(1-depth 대댓글) · 등록 · 대댓글 · (본인 댓글) 수정/삭제(soft)
        └ (작성자 또는 ADMIN) "수정" → 게시글 수정 페이지 / (작성자의 임시저장 글) "발행"

[게시글 작성 페이지] 카테고리 선택·제목·본문 입력(첨부 없이) → "임시저장" 또는 "발행" → 성공 → 상세/목록
  └ 첨부가 필요하면 "임시저장글 불러오기" 토글(F308 재사용) → 목록에서 방금 저장한 글을 **사용자가 직접 선택** → 게시글 수정 페이지로 이동해 첨부 진행
[게시글 수정 페이지] 편집 초기값 로드 → 수정·첨부 추가/삭제 → 저장(modifiedAt 갱신)/발행 → 상세 재조회
[내 임시저장함] 항목 클릭 → 이어쓰기(수정 페이지) / "발행" → 성공 → 목록 재조회
```

**권한 분기점**

- 라우트 가드(Layer 1): 미인증 → 로그인 리디렉션(auth PRD 관할). 게시판 전 페이지 최소 요구 role `EMPLOYEE`.
- 작성/댓글 액션: 서버가 **활성 사원**을 최종 판정(비활성/미승인 사원은 403). 프론트는 버튼을 노출하되 403을 권한 부족 UX로 처리.
- 소유권 액션(수정/발행/첨부관리 = 작성자 또는 ADMIN, 댓글 수정/삭제 = 댓글 작성자): 프론트는 `empId`/`writerEmpId`와 authStore 본인 식별자 비교로 버튼을 노출하되, **서버 403이 최종 판단**(우회 호출 시 권한 부족 UX). 이 도메인엔 `ROLE_003`(부서 불일치) 유발 기능 없음.
- 임시저장 글 접근: **작성자 본인만 조회 가능**(도메인 규칙). 타인 임시저장 글 상세 접근은 서버가 not-found/403 → 해당 UX.

### 2. MVP 필수 지원 기능(신규 기능ID 없음 — 표준 확정·기존 재사용)

- **페이징 UI 표준(흡수①)**: `BOARD_LIST`(F301)·`BOARD_COMMENTS`(F313) 응답의 Spring `Page` 메타(`number`(0-base)·`size`·`totalElements`·`totalPages`·`first`·`last`)로 페이지 컨트롤(이전/다음·페이지번호·total)을 구성하고, queryKey에 `page`/`size`를 포함한다. 이후 목록형 도메인이 복제할 표준.
- **파일 업로드/다운로드 표준(흡수②)**: F309~F312. 업로드는 `PATCH multipart`, 미리보기/다운로드는 인증 필요 GET(blob). 이미지 preview는 M5 blob objectURL 생명주기 표준을 재사용한다.
- **인증/셸/에러매핑**: 로그인·세션복원·공통 셸·`handleApiError`·`useZodForm`/서버검증 에러매핑은 `finish_1`/`finish_2` 관할(재서술 안 함).

### 3. MVP 이후 기능 / 이번 슬라이스 명시적 제외

- **좋아요 토글(생성/취소)** — ⚠️ **계약 미존재.** 도메인 모델에 `BoardLike` 엔티티(create/delete)는 있으나 `api-endpoint.md`에 **좋아요 관련 REST 엔드포인트가 노출되어 있지 않다**(전체 인덱스 grep 결과 0건). 따라서 이번 PRD는 **좋아요 수(`likeCount`) 읽기 표시만**(F303 상세에 포함, `BOARD_DETAIL`/`BOARD_LIST` 응답 필드) 포함하고, **토글 액션은 엔드포인트가 없어 구현 불가 → 열린 항목(§착수 전 확정 필요)으로 백엔드와 논의 후 별도 태스크화**. 근거 없는 발명 금지 원칙에 따라 토글 버튼은 이번 슬라이스에서 만들지 않는다.
- **카테고리별 최신 게시글 위젯(`BOARD_LATEST`)** — 계약은 존재하나 홈 대시보드 위젯 용도로, 이번 슬라이스의 목록→상세→작성 여정 밖이다. 홈 대시보드 PRD가 담당.
- **카테고리 CRUD/노출토글**(`CATEGORY_*`, ADMIN) — 별도 관리자 PRD.
- **게시글 검색/정렬 고급 필터** — 이번 스코프는 제목 keyword + 카테고리 필터 + 기본 페이징까지.
- **좋아요 누른 사람 목록·즐겨찾기·댓글 알림·멘션·실시간(STOMP) 갱신** — 별도 PRD(게시판은 재조회로 충분).
- 테마/다크모드, 다국어(i18n).

```

├── 게시글 작성 페이지: 임시저장글 불러오기(F308 재사용) 토글 → 항목 선택 시 게시글 수정 페이지로 이동
├── 게시글 상세 페이지: 다운로드(F310)/미리보기(F311)/댓글(F313~F317) · (작성자·ADMIN) 수정(F307)/발행(F306)
```

- 신규 메뉴 "게시판"을 선언적 권한 사이드바(S2) 배열에 `minRole: EMPLOYEE`로 **항목만 추가**(배관 재작업 없음).
- 소유권/활성 사원 조건 액션은 별도 메뉴가 아니라 페이지 내부에서 `hasRequiredRole` + 본인 식별자 비교로 조건부 렌더하고, 최종 판단은 서버 403에 위임한다.
- ADMIN은 RoleHierarchy상 전 메뉴·작성자 액션(수정/발행/첨부관리) 접근 가능(별도 ADMIN 섹션 불필요).

## 🚧 착수 전 확정 필요 (열린 항목 — 백엔드 논의)

1. **좋아요 토글 엔드포인트 부재** — `api-endpoint.md` 전체에 좋아요 관련 REST 엔드포인트가 없다(도메인 모델 `BoardLike`만 존재). `likeCount` **표시**만 가능하고 **토글은 구현 불가**. 백엔드에 좋아요 생성/취소 엔드포인트 노출 여부를 확인한 뒤 별도 태스크화한다(추측 구현 금지).
2. **댓글 삭제 권한** — 도메인 모델은 "작성자 또는 관리자"이나 `COMMENT_DELETE` 계약 권한은 "댓글 작성자"다. 프론트는 계약 기준으로 **작성자에게만 삭제 버튼 노출**하고, ADMIN 삭제 허용 여부는 서버 응답(403 여부)으로 확인 후 필요 시 반영.
3. **다중 첨부 업로드 방식** — `BOARD_FILE_UPLOAD` request-parts는 단수 `file` 1개만 문서화됨. 10개 첨부를 파일별 반복 호출로 처리할지, 다중 part로 한 번에 보낼지 실측/논의로 확정(현재는 파일별 순차 PATCH를 기본안으로 //todo 플래그).

> **해결됨(설계 확정 — 백엔드 논의 불필요)**: `BOARD_REGISTER`의 boardId 미반환 문제는 백엔드 변경 요청 없이 UX로 해결한다. 첨부가 필요한 글은 (1) 첨부 없이 임시저장 → (2) 게시글 작성 페이지의 "임시저장글 불러오기" 토글(F308 재사용)에서 **사용자가 직접** 방금 저장한 글을 목록(제목·최근수정시각)에서 선택 → (3) 확정된 boardId로 게시글 수정 페이지로 이동해 첨부 업로드. "가장 최근 updatedAt" 같은 자동 추정/휴리스틱은 사용하지 않는다 — 다건 임시저장 상태에서 오배치를 유발하기 때문이다.
