# 일반 기안(General Draft) 작성/수정 Frontend MVP PRD

> 이 PRD는 전자결재 도메인 5분할 중 **②일반 기안 관심사** — 일반 기안서(`draftType == GENERAL`)의 **작성(임시저장 생성 / 생성+상신)과 수정** — 만 다룬다. 유형과 무관한 **상세조회·문서함 5종·상신/철회/취소·승인/반려/공람·첨부 뷰**는 **①공통(`docs/prd/7.approval-common-prd.md`, 구현 완료 `src/features/approval/**`, `docs/ROADMAP(DRAFT).md` 28/28)** 소유이며 여기서 재구현하지 않고 **소비**한다.
>
> **경계 요약** — ②가 소유: 일반 기안 작성 페이지·수정 페이지, 그 API/mutation(`GENERAL_DRAFT_CREATE`/`_CREATE_SUBMISSION`/`_UPDATE`), 작성 폼 zod 스키마, 상세 `[수정]` 버튼의 실제 라우팅 배선, "새 기안 작성" 진입점. ②가 소비(①소유, 재구현 금지): 상세 페이지·`DraftTypeBody`(GENERAL 본문 렌더)·`DrafterActions`(수정 노출 판정 `resolveDrafterActions.canEdit`)·`EmployeePicker`(결재선 선택)·`ApproverParam` 타입·`approvalKeys`·`useDraftDetailQuery`(수정 프리필)·첨부 업로드(F716 `DRAFT_FILE_UPLOAD` + `useDraftFileUploadMutation`). 배관: axios·QueryClient·`handleApiError`·`ProtectedRoute`·LayoutShell·`useZodForm`/`submitWithErrorMapping`·shadcn 폼·sonner.
>
> 전역 계약(인증·reissue·에러·`ROLE_003`·페이징·날짜 dayjs·`withCredentials`)은 CLAUDE.md §7 `BACK-END 계약 문서` 관할이며 재서술하지 않는다.

## 🎯 핵심 정보

- **목적**: 활성 사원이 유형 슬롯 없는 **일반 기안서(제목·본문·결재선·첨부)** 를 작성해 임시저장하거나 바로 상신하고, 상신 전(UNSUBMITTED) 임시저장 기안을 상세/임시저장함에서 열어 수정하는 화면을 구성한다. 작성 후에는 ①공통의 상세·문서함·워크플로우로 이어진다.
- **사용자**: 최소 요구 role `EMPLOYEE`(활성 사원). 작성은 활성 사원 누구나, **수정은 해당 기안의 기안자 본인**만(서버 최종 판정). role 분기 없음(`ADMIN`은 RoleHierarchy상 포함).

## 🚶 사용자 여정

```
[사이드바 "전자결재 > 새 기안 작성"] → 일반 기안 작성 페이지
  ├ 제목·본문 입력 + 결재선 지정(EmployeePicker=①재사용) + (선택) 첨부
  ├ [임시저장으로 생성](GENERAL_DRAFT_CREATE, 201 {draftId})
  │    └ 성공 → 생성된 기안 상세 페이지(①) → (기안자·UNSUBMITTED) 상신/수정/첨부
  └ [생성 후 상신](GENERAL_DRAFT_CREATE_SUBMISSION, 201 {draftId})
       └ 성공 → 생성된 기안 상세 페이지(①, WAITING)

[전자결재 > 임시저장함(①)] → 행 클릭 → 기안서 상세 페이지(①)
  └ (기안자·UNSUBMITTED·GENERAL) [수정] 버튼(DrafterActions=①) → 일반 기안 수정 페이지
        ├ 기존 값 프리필(DRAFT_DETAIL 소비=①)
        └ [저장](GENERAL_DRAFT_UPDATE, 204) → 성공 → 상세 페이지로 복귀
```

**권한 분기점**

- 라우트 가드(Layer 1): 미인증 → 로그인 리디렉션(auth 관할). 작성·수정 라우트 모두 최소 요구 role `EMPLOYEE`. 별도 role 게이트 없음.
- 서버 최종 판단(role 아닌 문서-사원 관계):
  - **작성**(`GENERAL_DRAFT_CREATE`/`_CREATE_SUBMISSION`)은 활성 사원. 비활성/미승인 사원은 서버가 도메인 에러로 막음(가입 승인 플로우는 auth 관할).
  - **수정**(`GENERAL_DRAFT_UPDATE`)은 **기안자 본인 + 대상이 UNSUBMITTED**만. 그 외(타인·이미 상신됨) 접근 시 서버 일반 403 또는 도메인 에러 → 권한 부족/처리 불가 UX(재발급 금지, 에러코드 비의존).
  - **상신 시 결재선** 최소 1명 필요(도메인 규칙) → 서버 최종 판정. 프론트는 `[생성 후 상신]`에서 결재선 사전검증(Open Q#1).

## ⚡ 기능 명세

### 1. MVP 핵심 기능

| ID | 기능명 | 설명 | 근거 기능ID | 관련 페이지 |
|---|---|---|---|---|
| **[F720]** | 일반 기안서 작성(임시저장 생성 / 생성+상신) | 제목·본문 + (선택) 결재선(`approvers`) + (선택) 첨부로 일반 기안 생성. 한 폼의 **분리 버튼 2개**: `[임시저장으로 생성]`(UNSUBMITTED, `GENERAL_DRAFT_CREATE`) / `[생성 후 상신]`(WAITING, `GENERAL_DRAFT_CREATE_SUBMISSION`). 둘 다 `201 {draftId}` → 생성 기안 상세로 이동. 첨부는 생성으로 확보한 `draftId`에 F716로 업로드 | `GENERAL_DRAFT_CREATE` / `GENERAL_DRAFT_CREATE_SUBMISSION` | 일반 기안 작성 페이지 |
| **[F721]** | 일반 기안서 수정 | 상신 전(UNSUBMITTED) 임시저장 기안의 제목·본문·결재선을 수정(부분 수정, `PATCH`). 기존 값은 `DRAFT_DETAIL`(F701, ①)로 프리필. 기안자 본인만. `204` → 상세로 복귀 | `GENERAL_DRAFT_UPDATE` | 일반 기안 수정 페이지 |

### 2. MVP 필수 지원 기능 — 신규 기능ID 없음(①공통 자산 소비, 참조만)

②는 다음을 **재구현하지 않고 소비**한다(경계 = 헤더 인용 블록):

- **기안서 상세 페이지 + `DraftTypeBody`(GENERAL=`content` 렌더)** — 작성/상신/수정 성공 후 도착지. ①소유.
- **`DrafterActions` + `resolveDrafterActions.canEdit`** — 상세의 `[수정]` 노출 판정(기안자 + UNSUBMITTED)은 ①이 이미 계산. ②는 그 버튼 클릭 시 실제 라우팅만 배선(현재 `handleEdit`은 "준비 중" 토스트 placeholder → **일반 기안(슬롯-null 판별, §상세 [수정] 배선)**이면 수정 페이지로 `navigate`, 타 유형은 폴백 유지).
- **`EmployeePicker`(제어형)·`ApproverParam{approverId,role,order}`** — 결재선 선택 UI와 payload 타입. 선택 순서 → `order`(1-base), `role`은 `APPROVER` 고정(협조 결재자 지정은 범위 밖, ①선례 동일).
- **첨부 업로드 F716 `DRAFT_FILE_UPLOAD`(`useDraftFileUploadMutation`)** — 생성 응답 `draftId`로 재사용. 첨부 정책 `@docs/backend-contract/file-upload.md` + `@../docs/도메인모델.md`.
- **`useDraftDetailQuery`(F701)** — 수정 페이지 기존 값 프리필 소스.
- **폼 배관** `useZodForm`/`submitWithErrorMapping`(`@/shared/lib/form`)·`handleApiError`·`approvalKeys`(성공 후 invalidate) — board/취소기안 선례 동일.

### 3. MVP 이후 기능 / 범위 외 (이번 PRD 명시적 제외)

- **유형 슬롯 작성/수정 전부**: `LEAVE_DRAFT_*`(④연가), `BUSINESS_TRIP_DRAFT_*`·`BUSINESS_TRIP_PARTICIPANTS_UPDATE`(③출장), `SALES_DRAFT_*`(⑤매출) — 각 유형 작성 PRD 관할. ②는 GENERAL만.
- **상세조회·문서함 5종·상신/철회/취소·승인/반려·공람·첨부 뷰·워크플로우 액션** — ①공통 소유(`docs/prd/7.approval-common-prd.md`).
- **첨부 후처리(미리보기/다운로드/삭제)** — 상세 페이지 첨부 영역(F717~F719)으로 ①소유. ②의 작성/수정 폼은 **업로드 진입만** 다룬다.
- **결재선 협조 결재자(`COOPERATOR`) 역할 지정 UI** — MVP 범위 밖(APPROVER 고정).
- **테마/다크모드·다국어(i18n)·브라우저 푸시 알림** — 전 도메인 공통 제외.

| **다음 이동** | 생성 성공(201 `{draftId}`) → 생성 기안 상세 페이지(①) + `approvalKeys` invalidate + 성공 토스트(sonner). 검증 실패 → 인라인/root 에러, 상신 규칙 위반(결재선 없음 등) → 에러 토스트, 권한 없음 → 안내 UX |

### 일반 기안 수정 페이지

> **구현 기능:** `F721` | **메뉴 위치:** (비노출) 상세 [수정] · 임시저장함 → 상세 → [수정]

| 항목 | 내용 |
|---|---|
| **역할** | 상신 전(UNSUBMITTED) 임시저장 일반 기안의 제목·본문·결재선을 수정하는 화면 |
| **진입 경로** | 기안서 상세 페이지(①)의 기안자 액션 `[수정]`(`DrafterActions`, `canEdit` = 기안자 + UNSUBMITTED) → GENERAL 유형일 때만 이 페이지로 라우팅(②가 배선). 직접 URL 진입 시 상세 재검증 |
| **접근 권한** | 최소 요구 role: `EMPLOYEE` / 서버 최종 판단: **기안자 본인 + UNSUBMITTED**만 수정 가능. 타인·이미 상신된 기안은 서버 403 또는 도메인 에러 → 권한 부족/처리 불가 UX(재발급 금지). 프론트는 프리필 상세로 **일반 기안 여부(슬롯-null 판별: `leave`/`businessTrip`/`sales`/`sourceDraftId` 전부 null)**·UNSUBMITTED·기안자 여부를 확인해 폼을 노출하되 최종 판단은 서버 |
| **사용자 행동** | 프리필된 제목·본문·결재선 확인/수정 후 `[저장]` |
| **주요 기능** | • 기존 값 프리필(`DRAFT_DETAIL`=F701 소비, `title`/`content`/`approvers[]`→`EmployeePicker` 초기 선택 복원) • 제목·본문·결재선 수정 + zod 사전검증 • **`[저장]`**(`GENERAL_DRAFT_UPDATE`, `PATCH {title?,content?,approvers?}` 부분 수정, `204`) • 첨부는 이 폼 범위 밖 — 상세 첨부 영역(①)에서 관리 |
| **다음 이동** | 저장 성공(204) → `approvalKeys.draftDetail`/목록 invalidate + 상세 페이지로 복귀 + 성공 토스트. 검증 실패 → 인라인/root 에러, 권한/상태 위반 → 에러 토스트 후 상세로 유도 |

### 기안서 상세 페이지 — `[수정]` 진입 배선 (①소유 페이지에 ② 배선 추가)

> **구현 기능:** (배선) `F721` 진입 · `DrafterActions`(①) `canEdit` 소비 | **별도 페이지 아님**

- ①의 `DrafterActions.handleEdit`는 현재 "해당 유형 작성 화면은 준비 중입니다" 토스트 placeholder다(Open Q#3, ①공통). ②는 이를 **일반 기안일 때 일반 기안 수정 페이지로 `navigate`** 하도록 실배선하고, 휴가/출장/매출 유형은 각 유형 PRD 착수 전까지 폴백 토스트를 유지한다.
- **일반 기안 판별은 `draftType` 문자열 비교를 쓰지 않는다** — 실측상 `draftType`은 백엔드 `getClass().getSimpleName()` 값(일반기안 = **`"GeneralDraft"`**, `"GENERAL"` 아님. UX 실측 `GET /api/drafts/6` 응답 확인, 스니펫의 `"BUSINESS_TRIP"`은 outdated). 대신 ①의 `DraftTypeBody`가 채택한 **슬롯-null 판별**과 동형으로 판별한다: `draft.leave == null && draft.businessTrip == null && draft.sales == null && draft.sourceDraftId == null`(유형 슬롯 전부 null + 취소기안 아님 = 순수 일반 기안). 이 술어를 `DrafterActions`의 수정 라우팅과 수정 페이지 진입 가드에 공통 적용한다.
- 노출 판정(`canEdit` = 기안자 본인 + UNSUBMITTED)은 ①이 이미 계산하므로 ②는 판정 로직을 재작성하지 않는다.

> **참고**: 로그인/회원가입/승인 대기, 공통 셸(헤더·사이드바·푸터), 문서함·상세·워크플로우는 auth·shell·①공통 PRD 관할이며 여기서 재정의하지 않는다.

## 🗂️ 참조 계약 매핑

> 필드는 `back/build/generated-snippets/<기능ID>/`의 request-fields·request-body·response-body를 직접 대조해 기술(추측 아님). **approvers 형태 실측**: 작성/수정 3종은 모두 `{...}` 객체 안에 `approvers` 키로 중첩된 객체 배열이다(취소기안과 동일). ①의 `DRAFT_SUBMIT`만 최상위 bare array다.

| 페이지 | 도메인 스킬 | 근거 기능ID | 핵심 DTO/타입 · 필드(스니펫 실측) | 비고 |
|---|---|---|---|---|

**계약 실측 메모:**
- **`draftType` 실측(⚠️ Major 교정 반영):** `DRAFT_DETAIL` 응답의 `draftType`은 백엔드 `getClass().getSimpleName()` 값이다 — 일반기안 = **`"GeneralDraft"`**(UX 실측 `GET /api/drafts/6` 응답 확인). `"GENERAL"`이 아니며, DRAFT_DETAIL 스니펫의 `"BUSINESS_TRIP"`은 outdated(현재 서버는 `"BusinessTripDraft"` 계열로 추정). **유형 판별은 `draftType` 문자열 비교를 금지하고, ①의 `DraftTypeBody`와 동형인 슬롯-null 판별로 한다**: 일반기안 = `leave`·`businessTrip`·`sales`·`sourceDraftId` 전부 null(순수 일반 기안). 이 규칙은 ③출장(`businessTrip` non-null)·④연가(`leave` non-null)·⑤매출(`sales` non-null)·취소기안(`sourceDraftId` non-null) 판별에도 공통 적용된다(COMPLICATED-DOMAIN 후보 규약).
- **작성 body 구조(GENERAL_DRAFT_CREATE / _CREATE_SUBMISSION 동일):** `{ "title": "...", "content": "...", "approvers": [ { "approverId": 2, "role": "APPROVER", "order": 1 } ] }`. approvers 항목 필드명은 **`approverId`/`role`/`order`** — 기존 `ApproverParam` 타입과 정확히 일치(신규 타입 발명 불필요).
- **응답:** 두 생성 API 모두 `201` + `{ draftId: number }`(단일 필드). 취소기안 생성(F704) 응답과 동형 → 생성 후 `/approval/drafts/{draftId}` 상세로 이동하는 ①선례 재사용.
- **수정:** `204` Empty(본문 없음). 세 필드 모두 optional이나, 실사용은 폼 전체 값을 보내는 전량 갱신으로 단순화 가능(부분 전송도 계약상 허용).
- **첨부 정책(drafts 도메인, ①실측 재확인):** 확장자 게시판과 동일(`pdf,doc,docx,xls,xlsx,ppt,pptx,txt,csv,png,jpg,jpeg,gif,zip`), 파일당 20MB(file-upload.md), **기안서당 최대 10개·총 10MB**(도메인모델). 위반 에러 `FILE_001~005`.

## ❓ Open Questions (계약 공백 — 개발 착수 전 확인 필요)

1. **상신 시 결재선 필수 검증 위치.** `GENERAL_DRAFT_CREATE_SUBMISSION`의 request-fields는 approvers를 optional(false)로 문서화하지만, 도메인모델은 "상신 = 결재자 1명 이상 필수, 결재자 목록은 null·빈 배열 불가"로 규정한다(표면 불일치). 프론트 권고안: `[임시저장으로 생성]`은 결재선 없이 허용, `[생성 후 상신]`은 **결재선 최소 1명을 클라 사전검증**(취소기안 다이얼로그는 현재 미검증·서버 위임 → 일관성 정책 확정 필요). 최종 검증은 서버.
2. **작성 후 이동 목적지.** 생성/상신 응답이 `{draftId}`이므로 ①선례(취소기안)대로 생성 기안 상세(`/approval/drafts/{draftId}`)로 이동하는 것으로 가정. 임시저장 시 상세 대신 임시저장함으로 보낼지 여부 확정 필요(board는 boardId 미반환이라 목록 이동이었으나, general draft는 draftId 반환 → 상세 이동 가능).
3. **작성 폼 첨부 UX(생성 전 선택 → 생성 후 업로드).** 작성 API는 JSON body(파일 파트 없음)이고 F716은 `draftId` 필요. 따라서 "생성 성공 후 선택 파일들을 순차 F716 업로드" 흐름이 되는데, ① 생성+상신을 함께 눌렀을 때 첨부 업로드 실패 시 롤백/재시도 UX, ② 다중 파일(part명 `file` 단수, 1요청=1파일 → 순차 반복) 처리, ③ 총 10개·10MB 클라 사전검증 범위 확정 필요. 대안: 작성 폼은 첨부 없이 생성 → 상세 첨부 영역(①)에서 업로드하도록 단순화(권고).
4. **"새 기안 작성" 유형 선택 허브 필요 여부.** MVP는 유형 선택 없이 일반 기안 작성으로 직결한다. ③출장/④연가/⑤매출 착수 시 유형 선택 화면을 둘지, 사이드바에 유형별 항목을 나열할지 확정 필요(이번 범위는 일반만).
5. **상세 `[수정]` 유형 분기 소유권.** `DrafterActions.handleEdit`의 유형별 라우팅(GENERAL→②수정 페이지 / LEAVE·BUSINESS_TRIP·SALES→각 유형)은 유형이 늘수록 분기가 커진다. ②가 GENERAL 분기만 배선하고 나머지는 폴백 유지 → 각 유형 PRD가 자기 분기를 추가하는 방식으로 가정(분기 확장 규약 확정 필요).

**🔍 5단계: 누락/고아**
고아 기능·페이지·메뉴 없음 ✅. 상세·문서함·워크플로우·첨부 뷰는 ①소유로 "범위 외" 명시(누락 아님), LEAVE/BUSINESS_TRIP/SALES 작성은 각 유형 PRD로 격리 ✅. 상신 결재선 검증·작성 후 이동·첨부 UX·유형 허브 등 잔여 공백은 Open Questions(#1~#5)로 격리(발명 아님) ✅.
