## 개요
`$1`(별도 서버에서 편집한 UI 링크)을 기준으로, 우리 프로젝트에 맞는 화면을 이식한다.
UI 이식은 `@ux-ui-stylist`, 라우팅 로직은 `@react-router-developer`, 테스트는 `@test-author-runner`에 위임한다.
이 명령은 지휘만 하며, 서브에이전트 간 직접 대화가 불가능하므로 **메인 세션이 중계**해 정합을 맞춘다.

> 라우팅↔UI 왕복이 잦아 이 순차 중계 방식으로 감당이 안 되면, `.claude/docs/adapt-ui-team.md`(Agent Teams 플레이북 — 팀원 직접 조율)로 전환하는 것을 사용자에게 제안한다.
> 팀 전환 시 필요한 **사전 설정(0)과 파일 소유권 규칙(0-2)은 그 문서에 정의**되어 있다.

## 인자
- `$1` **reference-url**: 레퍼런스 UI 링크. 비어 있으면 **실행하지 말고** 링크를 사용자에게 되묻는다.
- `$2` **target**: 이식 대상 화면/route 설명(예: "휴가 신청 폼 화면 /leave/new"). 비어 있으면 되묻는다.
- `$3` **test**: `false`면 테스트 단계를 건너뛴다. 미지정 시 `true`.

## 공통 규칙
- **커밋 금지**: 자동 커밋하지 않는다. 커밋은 사용자 확인 후에만.
- **레퍼런스는 참고용**: `$1`은 디자인/레이아웃/상호작용의 기준일 뿐, 우리 프로젝트의 디자인 시스템·컴포넌트·컨벤션을 우선한다. 레퍼런스 코드를 그대로 복붙하지 않는다.
- **카드 배치는 레퍼런스를 그대로 따른다**: 카드의 그리드/순서/정렬 등 배치는 레퍼런스 화면과 동일하게 재현한다.
- **공통 레이아웃은 무시한다**: 레퍼런스의 공통 레이아웃(헤더·바디·푸터)은 따르지 않는다. 공통 레이아웃은 우리 프로젝트 것을 사용하고, 레퍼런스에서는 **공통 레이아웃 외의 콘텐츠 프레임만** 이식 대상으로 삼는다.
- **링크 확인**: `$1`은 사용자 본인 서버로 간주하되, 도메인이 예상과 다르면 진행 전 사용자에게 확인한다.
- **복잡 판단은 절차적 사고**: 라우팅 구조·상태 흐름이 복잡하면 `sequential-thinking` MCP로 단계적으로 사고한다.

# 실행 단계

## 0. 사전 확인
- `$1` 또는 `$2`가 비어 있으면 되묻고 중단한다.

## 1. 레퍼런스 UI 열람
- `Playwright MCP`로 `$1`을 열어 레퍼런스를 캡처한다: **공통 레이아웃(헤더/바디/푸터)을 제외한 콘텐츠 프레임**, 그 안의 **카드 배치(그리드/순서/정렬)**, 주요 컴포넌트, 상호작용(입력→동작→결과), 상태 변화(로딩/에러/빈 상태).
- 이식에 필요한 요구사항을 요약한다. (이후 위임 시 이 요약을 근거로 전달)

## 2. 라우팅 선행 판단 — `@react-router-developer`
- 이번 화면에 라우팅 로직이 필요한지 판단한다: 신규 route, 경로 파라미터, 중첩/레이아웃 라우트, 가드/리다이렉트, 데이터 로더 등.
- 필요하면 **먼저** `@react-router-developer`에게 라우팅 골격을 위임한다. (route 배선/파라미터/가드 정의 → UI가 얹힐 뼈대 확보)
- 라우팅이 불필요한 순수 화면이면 이 단계를 건너뛴다.

## 3. UI 이식 — `@ux-ui-stylist`
- `@ux-ui-stylist`에게 1단계 레퍼런스 요약을 기준으로 화면 구현을 위임한다.
- 2단계에서 라우팅 골격이 잡혔다면, **그 route/파라미터 계약 위에** UI를 얹도록 명시한다(진입 파라미터 소비, 네비게이션 트리거 지점 포함).

## 4. 정합성 패스 (메인 세션 중계, 1~2회)
- 라우팅과 UI가 맞물리는 지점을 점검한다: 네비게이션 동작, 경로 파라미터 소비, 로딩/에러/가드 상태의 화면 반영.
- 어긋나는 부분이 있으면 해당 에이전트에게 **범위를 좁혀** 보정 위임한다:
  - 경로/파라미터/가드 문제 → `@react-router-developer`
  - 레이아웃/상태 표현/컴포넌트 문제 → `@ux-ui-stylist`
- 정합이 맞을 때까지 최대 2회 왕복하고, 그 이상 얽히면 사용자에게 상황을 보고하고 판단을 구한다(왕복이 근본적으로 잦은 작업이면 `.claude/docs/adapt-ui-team.md` 전환을 함께 제안).

## 5. 테스트 — `@test-author-runner` (`$3` = true 시)
- 이번 작업이 **변경한 파일 범위를 명시**하여 `@test-author-runner`에게 테스트 작성/실행을 위임한다.
- 라우팅이 포함됐다면 라우팅 동작(진입/파라미터/가드)도 테스트 대상에 포함하도록 명시한다.

## 5-1. 실패 시 수정 루프 (2 ↔ 3 반복)
- 테스트에서 오류가 나오면, 실패 원인을 분류해 **2·3 단계로 되돌아가** 수정한다.
  - 경로/파라미터/가드 등 라우팅 원인 → **2단계** `@react-router-developer` 재위임
  - 레이아웃/상태 표현/컴포넌트 등 UI 원인 → **3단계** `@ux-ui-stylist` 재위임
  - 원인이 걸쳐 있으면 두 단계를 함께 돌리고, 4단계 정합성 패스로 다시 맞춘 뒤 재테스트한다.
- 수정 후에는 반드시 5단계 테스트를 다시 실행한다. (수정 → 재테스트를 통과할 때까지 반복)
- 같은 원인으로 3회 이상 반복되거나 원인이 도메인/백엔드 등 이 명령 범위를 벗어나면, 반복을 멈추고 사용자에게 상황을 요약 보고한 뒤 판단을 구한다(반복의 원인이 라우팅↔UI 왕복 자체라면 `.claude/docs/adapt-ui-team.md` 전환도 함께 제안).

## 6. 마무리 보고
- 이식 결과, 라우팅 변경 사항, 미해결 이슈(정합성 왕복 초과·UX 문제·테스트 실패)를 요약 보고한다.
- **커밋은 하지 않는다.** 다음 액션을 사용자에게 안내하고 종료한다.
