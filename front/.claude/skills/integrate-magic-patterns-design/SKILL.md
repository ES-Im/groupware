# Integrate a Magic Patterns Design (this project's stack)

Magic Patterns generates **prototypes**. The code you receive is a high-fidelity design spec — it shows layout, hierarchy, spacing rhythm, interactions, and intent. It is NOT meant to be pasted into the codebase as-is.

**The golden rule: when the Magic Patterns code and this project disagree, the project wins.** Reproduce the *design*, not the exact code. Always prefer this project's existing components, design tokens, styling system, data layer, and conventions over the literal values in the prototype.

## This project's fixed stack

The stack is **fixed**. Do NOT introduce a new library to match the prototype — if the prototype needs something the stack can't do, stop and discuss with the user before adding anything.

| Layer | This project uses | Magic Patterns default | Action |
|---|---|---|---|
| Runtime/build | **React 19 + Vite** | React 18 + Vite | Discard the prototype's Vite scaffolding; the project already has its own. Watch for React 18-only patterns. |
| Language | **TypeScript** | TypeScript | Match. |
| Routing | **React Router 7** | react-router-dom | Rewrite routes/links for React Router 7 (`react-router` package, data APIs / `createBrowserRouter`, `<Link>`, `<NavLink>`, `useNavigate`). Do NOT keep `react-router-dom` v6 patterns blindly. |
| UI/styling | **Tailwind CSS v3 + shadcn/ui** | Tailwind v3 utilities | Same Tailwind version — utility classes port cleanly. But replace hand-rolled elements with **shadcn/ui** primitives (see mapping below). |
| Icons | **lucide-react** (shadcn default) | lucide-react | **Match — keep the icons as-is.** |
| HTTP | **axios** | none (mock data) | Replace mock data with real calls via the project's axios client/instance. |
| Server state | **@tanstack/react-query** | `useState` + mock arrays | Wire data through react-query (`useQuery`/`useMutation`), not local component state. |
| Client state | **zustand** | local `useState` | Cross-component/shared UI state → a zustand store. Keep purely-local UI state in `useState`. |
| Forms + validation | **react-hook-form + zod (+ @hookform/resolvers)** | controlled `useState` + no-op `onSubmit` | Rebuild forms with react-hook-form; define a zod schema; wire `zodResolver`. Replace stub submit handlers with real mutations. |
| Realtime (chat) | **@stomp/stompjs** (STOMP over native WebSocket, no SockJS) | none | If the prototype implies live updates, wire to the existing STOMP client. Do not add socket.io or SockJS. |
| Dates | **dayjs** | ad hoc / `Date` | Format/parse with dayjs. |
| Tables/grids | **@tanstack/react-table** | hand-rolled `<table>` markup | Rebuild data tables with @tanstack/react-table + shadcn Table primitives for markup. |
| Calendar | **@fullcalendar/react** | hand-rolled / none | Use FullCalendar for calendar views. |
| Charts | **Recharts** | recharts | **Match — keep the charts, restyle with project tokens.** |
| Editor | **Tiptap** | none / `<textarea>` | Rich-text areas → Tiptap. |
| Notifications/toasts | **sonner (+ shadcn AlertDialog)** | none / inline banners | Toasts → sonner's `toast()`. Confirm/destructive dialogs → shadcn `AlertDialog`. |

Two things line up out of the box — **lucide-react icons** and **Recharts** — so port those nearly directly (just restyle). Everything else gets mapped onto the stack above.

## What Magic Patterns code looks like

Unless the design used a custom design system, expect:

- React 18 + TypeScript, styled with **Tailwind CSS v3** utility classes
- **lucide-react** icons, **framer-motion** animations, **react-router-dom** routing, **recharts** charts
- Named exports (`export function PricingSection`), flat/shallow file structure (`components/`, `pages/`, `utils/`)
- **Hardcoded mock data** — inline arrays/objects or a `utils/mockData.ts`
- Placeholder images as full URLs (often Unsplash)
- Stubbed interactivity: controlled inputs with local `useState`, `onSubmit` handlers that do nothing, no API calls, no auth, no backend
- Zip/GitHub exports wrapped in a standalone Vite project (`vite.config.ts`, `index.html`, `src/`)

Designs built on a design system preset (shadcn/ui, Chakra, Mantine, MUI) will use that library's components/theming instead of plain Tailwind. **If the prototype already targets shadcn/ui, you're in luck — map its components straight onto this project's `components/ui/`.**

## Workflow

### Step 1: Inventory the prototype
Read all the Magic Patterns files first. Identify:
- The actual design content: components, layout, screens, interactions, states (hover, empty, loading, error if present)
- Mock data shapes — these hint at the real data model the UI expects (turn them into zod schemas / TS types)
- Which parts are scaffolding to discard (see checklist below)

**Discard checklist** — never port these:
- [ ] `index.tsx` / `index.html` / `vite.config.ts` / `tsconfig*.json` / `postcss.config.js` / `package.json` / `.eslintrc*` — Vite scaffolding; the project already has its own
- [ ] `tailwind.config.js` and `index.css` — **merge only genuinely new tokens** into the project's existing Tailwind v3 config; never overwrite or fork it
- [ ] `canvas.manifest.js`, `useScreenInit.js` — Magic Patterns multi-screen plumbing; replace with real React Router 7 routes
- [ ] `ComponentPreview.tsx`, `components.config.json`, `context.md` — editor preview files
- [ ] `_designSystem/` folders and empty component stub files — precompiled design system bundles
- [ ] `data-id` props on elements — editor instrumentation
- [ ] `utils/mockData.ts` and inline mock data — replace with the real data layer (axios + react-query)
- [ ] `framer-motion` usage — **not in this stack.** Reimplement with Tailwind transitions / `tailwindcss-animate` (shadcn's animation dep) or CSS. Do NOT add framer-motion.

### Step 2: Survey the target codebase
Before writing anything, confirm how this project actually wires things up (the stack is fixed, but paths/conventions vary):
1. **Routing** — find the React Router 7 route definition (`createBrowserRouter` / route modules). Match its convention for pages, layouts, links, and navigation.
2. **shadcn/ui components** — list what's already in `components/ui/` (Button, Input, Card, Dialog, Select, Badge, Table, Tabs, AlertDialog, …). Reuse these; don't duplicate them.
3. **Tailwind theme** — read the project's `tailwind.config` (v3) and CSS variables for colors, spacing, radii, typography, breakpoints. These are the semantic tokens to snap to.
4. **Data layer** — find the axios instance/base client and the react-query setup (query client, query key conventions, existing hooks).
5. **State** — find existing zustand stores and their patterns.
6. **Forms** — find existing react-hook-form + zod usage to match schema/resolver conventions.
7. **Conventions** — export style, file naming, folder placement, i18n, accessibility patterns.

Shortcut: find an existing page/feature similar in shape to the new design and use it as the structural template.

### Step 3: Map prototype pieces to stack equivalents

| Prototype has | Do this |
|---|---|
| Hand-rolled `<button className="px-4 py-2 bg-blue-600...">` | Use shadcn `<Button>` with the nearest variant |
| Hand-rolled inputs, selects, modals, dropdowns, tabs | Use shadcn primitives (`Input`, `Select`, `Dialog`, `DropdownMenu`, `Tabs`, …) |
| Confirm/delete dialogs, destructive actions | shadcn `<AlertDialog>` |
| Toasts / inline success-error banners | `sonner` — `toast.success()` / `toast.error()` |
| Raw hex/arbitrary colors (`bg-[#4F46E5]`, `text-blue-600`) | Nearest semantic token (`bg-primary`, `text-muted-foreground`, …) from the project's Tailwind theme |
| Exact pixel values (`w-[347px]`, `gap-[18px]`) | Snap to the Tailwind spacing/sizing scale (`gap-4`, `w-80`, …) |
| Hardcoded fonts / Google Font `@import`s | Use the project's existing typography setup |
| lucide-react icons | **Keep as-is** (lucide-react is the stack's icon lib) |
| recharts charts | **Keep**, restyle with project theme colors/tokens |
| framer-motion animations | Reimplement with Tailwind transitions / `tailwindcss-animate` / CSS — do not add framer-motion |
| `react-router-dom` routes and `<Link>`s | React Router 7 routes + `<Link>`/`<NavLink>`/`useNavigate` from `react-router` |
| Mock data arrays | Wire to axios + react-query; derive zod schemas / TS types from the mock shapes |
| `useState`-only form handling | react-hook-form + zod (`zodResolver`); real submit → react-query mutation |
| Local `useState` for shared/cross-view UI state | zustand store |
| Hand-rolled data `<table>` | @tanstack/react-table + shadcn `Table` markup |
| Calendar/scheduling UI | @fullcalendar/react |
| Rich text `<textarea>` / contenteditable | Tiptap |
| Date formatting/parsing | dayjs |
| Live/streaming updates (chat, presence) | existing @stomp/stompjs client |
| Unsplash/placeholder image URLs | Real assets or the project's image/placeholder approach |

Only port a component wholesale when the project genuinely has no equivalent — and when you do, restyle it with the project's tokens and place it where the project keeps shared components (typically alongside `components/ui/` or a feature folder).

### Step 4: Implement
- Build in this project's file structure (React Router 7 pages/routes, `components/`, feature folders), not the prototype's. Keep the prototype's component *boundaries* (what's a section, card, reusable unit); drop its file paths.
- Preserve design intent: visual hierarchy, layout, relative spacing rhythm, responsive behavior, and interaction states. That's what the user approved in Magic Patterns.
- Treat exact values as approximations of intent. "16px gap" means "one step of normal spacing" → `gap-4` (or the project's token), not literal `gap-[16px]`.
- Add what prototypes always omit: real react-query loading/error/empty states, accessibility (labels, focus management, keyboard handling) per shadcn/Radix patterns, i18n if the project uses it, and real handlers/mutations.
- **Do not install new dependencies.** The stack is fixed. If nothing in the stack can do the job, stop and discuss with the user before adding anything.

### Step 5: Verify
1. Run the project's typecheck and linter; fix anything introduced.
2. Render the result and compare against the Magic Patterns design for *intent*: same hierarchy, layout, interactions — expressed in this project's visual language (shadcn/ui + the project's Tailwind tokens). Pixel-for-pixel parity with the prototype is not the goal; consistency with the rest of the app is.
3. Confirm no prototype artifacts leaked in: no mock data, no `data-id` props, no stray/forked Tailwind config, no `react-router-dom` imports, no `framer-motion`, no other unused new dependency.

## Common mistakes to avoid
- **Copying the prototype verbatim** and shipping a page that looks different from the rest of the app. The most common and most costly failure.
- **Duplicating primitives** — a second Button/Modal/Input that differs from the shadcn one already in `components/ui/`.
- **Importing the prototype's theme** — overwriting/forking `tailwind.config` or global CSS instead of mapping onto existing tokens.
- **Keeping mock data "for now"** — it gets shipped. Wire axios + react-query, or stub cleanly at the data-layer boundary, not inside components.
- **Matching arbitrary values exactly** (`w-[347px]`) instead of snapping to the Tailwind scale.
- **Leaving `react-router-dom` / `framer-motion`** in place instead of mapping to React Router 7 and Tailwind/CSS animation.
- **Adding any new library** to match the prototype. The stack is fixed — discuss first.
