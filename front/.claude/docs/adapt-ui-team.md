# adapt-ui — Agent Teams 플레이북

레퍼런스 UI를 프로젝트에 이식하는 작업을, `react-router-developer`(라우팅)와 `ux-ui-stylist`(디자인)가
**공유 세션(팀)**에서 지속적으로 협업하고, `test-author-runner`가 테스트하는 방식으로 수행한다.
Agent Teams는 슬래시 커맨드가 아니라 **세션 레벨 모드**다. 아래 사전 설정을 켠 뒤, 리드(메인 세션)가 킥오프 프롬프트로 팀을 구성한다.

---

## 0. 사전 설정 (최초 1회)

### 0-1. MCP 프로젝트 레벨 등록 (중요)
팀원은 **에이전트 정의의 `mcpServers` 를 로드하지 않고** 프로젝트 `settings.json` 의 MCP만 쓴다.
Playwright MCP(레퍼런스 열람 / UX 검증용)를 프로젝트 `settings.json` 에 등록한다.
등록이 어려우면 **브라우저/UX 검증은 리드가 직접 수행**한다(리드는 전체 MCP 사용 가능).

### 0-2. 파일 소유권 (충돌 방지)
팀 협업의 핵심은 **소유 파일이 겹치지 않게** 하는 것이다. 이 프로젝트의 실제 구조 기준 소유권은 아래로 확정한다(이 문서가 단일 출처).

```md
## Agent Teams — 파일 소유권 (adapt-ui)
- router  (@react-router-developer): src/app/router.tsx — 라우트 배선/파라미터/가드/레이아웃 네비게이션
- stylist (@ux-ui-stylist):          src/features/<domain>/** 의 비테스트 파일 — 컴포넌트/스타일/마크업
- tester  (@test-author-runner):     src/features/<domain>/**/*.test.{ts,tsx} 및 src/test/** — 테스트·목/셋업 인프라
- lead:   레퍼런스 스펙 관리, route↔UI 계약 통합 검토, 커밋 게이트(커밋은 사용자 확인 후에만)
```

> 테스트가 feature 폴더에 코로케이션되므로 stylist(비테스트)와 tester(테스트 파일)는 **파일 접미사**로 분리한다.
> 팀원은 이 문서를 자동 로드하지 않으므로, **리드가 킥오프 시 각 스폰 프롬프트에 위 소유권을 그대로 명시**한다(아래 1번 2단계 참고).

---

## 1. 리드 킥오프 프롬프트 (세션에 붙여넣기)

> 아래에서 `{REFERENCE_URL}`, `{TARGET}`(대상 화면/route 설명)만 채워 실행한다.

```
adapt-ui 작업을 Agent Team으로 진행한다.
- 레퍼런스: {REFERENCE_URL}
- 대상: {TARGET}

[리드가 직접 수행]
1. Playwright MCP로 레퍼런스 URL을 열어 스펙을 캡처한다:
   공통 레이아웃(헤더/바디/푸터)을 제외한 콘텐츠 프레임 / 그 안의 카드 배치(그리드·순서·정렬) /
   주요 컴포넌트 / 상호작용(입력→동작→결과) / 상태(로딩·에러·빈 상태).
   (URL이 예상 도메인과 다르면 멈추고 나에게 확인.)
   ※ 디자인 규칙: 카드 배치는 레퍼런스를 그대로 따르고, 공통 레이아웃은 무시한다
     (공통 레이아웃은 우리 프로젝트 것을 쓰고, 레퍼런스는 공통 레이아웃 외 프레임만 이식 대상).
   캡처한 요구사항을 스펙으로 정리해 태스크 설명에 넣는다.

2. TeamCreate 로 팀을 만들고 3명을 스폰한다. 각 팀원은 아래 에이전트 정의를 참조:
   - "router"  → .claude/agents/react-router-developer
   - "stylist" → .claude/agents/ux-ui-stylist
   - "tester"  → .claude/agents/test-author-runner
   각 스폰 프롬프트에 소유 파일 범위·수용 기준·제약을 구체적으로 명시한다(왕복 최소화).

3. 태스크를 의존성과 함께 배치한다:
   - T-route (router): 라우팅 골격(route 배선/파라미터/가드/로더). 라우팅이 불필요한 순수 화면이면 생략.
   - T-ui (stylist): 레퍼런스 스펙 기준 화면 이식. 라우팅이 있으면 T-route 에 blocked.
       디자인 규칙(필수): 카드 배치는 레퍼런스 그대로 재현, 공통 레이아웃(헤더/바디/푸터)은 무시하고
       우리 프로젝트 공통 레이아웃을 사용 — 레퍼런스는 공통 레이아웃 외 콘텐츠 프레임만 이식한다.
       router 와 stylist 는 route/props 계약을 SendMessage 로 **직접** 조율한다(리드 경유 금지).
   - T-test (tester): 변경 범위 테스트. T-ui / T-route 완료에 blocked.
       라우팅이 있으면 진입/파라미터/가드 동작도 테스트에 포함.

[실패 시 수정 루프 — 팀 내에서 반복]
4. tester 가 실패를 보고하면 원인을 분류해 해당 팀원에게 SendMessage:
   - 라우팅 원인(경로/파라미터/가드) → router
   - UI 원인(레이아웃/상태 표현/컴포넌트) → stylist
   - 걸쳐 있으면 둘 다. 팀원은 stateful 이므로 이전 맥락을 유지한 채 수정한다.
   수정 후 tester 재실행 → 통과할 때까지 반복. 리드는 TaskList 로 상태를 추적한다.
   같은 원인 3회 이상 반복되거나 원인이 도메인/백엔드 등 범위를 벗어나면 멈추고 나에게 보고.

[마무리 — 리드]
5. 통합 검토(route↔UI 정합, 콘솔 에러) 후 요약 보고: 이식 결과, 라우팅 변경, 미해결 이슈.
   커밋은 절대 하지 않는다. 다음 액션만 안내한다.
```

## 2. 협업 모델 요약

```
        ┌──────────────── lead (메인 세션) ────────────────┐
        │  레퍼런스 스펙 캡처 · 팀 생성 · 태스크/의존성 · 통합검토 · 커밋게이트 │
        └───────┬───────────────┬───────────────┬─────────┘
                │ spawn         │ spawn         │ spawn
             router ◀── SendMessage ──▶ stylist        tester
          (라우팅 소유)   route/props 계약   (UI 소유)   (테스트 소유)
                └──────── 실패 루프: tester → router/stylist 직접 수정 → 재테스트 ────────┘
```

- 팀원은 **지속 컨텍스트(stateful)** 라 2↔3↔테스트 왕복에서 맥락을 유지한다 → 격리 서브에이전트의 재브리핑 손실 문제가 사라진다.
- 팀원 간 **직접 메시지**로 route/UI 계약을 실시간 조율한다(리드 중계 불필요).

## 3. 주의사항 / 한계
- **커밋 금지**, 도메인 이탈 로직 변경은 사용자 확인 후.
- 팀원은 서브에이전트·다른 팀원·팀 생성 불가(허브앤스포크). 팀원 도구는 서브에이전트보다 적음(약 20종).
- `/resume`·`/rewind` 로 진행 중 팀원이 복구되지 않는다. 세션이 끊기면 재스폰 필요.
- 토큰 비용은 순차 대비 약 3~4배. 라우팅↔UI가 실제로 얽혀 왕복이 잦은 작업에서 그 값을 한다.
- 팀원의 skills/mcpServers 는 에이전트 정의가 아니라 프로젝트 `settings.json` 에서 로드됨(0-2 참고).

### 참고: 가벼운 대안
왕복이 적은 단순 이식이면 커맨드판 `adapt-ui`(격리 서브에이전트 순차 + 메인 중계)로 충분하다.
왕복이 잦아 공유 세션이 필요할 때 이 팀 플레이북을 쓴다.
